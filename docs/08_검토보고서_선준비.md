# 검토 보고서 — 말이 끝나기 전에 답을 준비하고, 끝나는 순간 내보낸다

> 2026-11-20 · 대상: 현재 상담원 구조(AGENT 트랙 round1 + AG-T15c) · 근거: `docs/decisions/*`

## 1. 핵심 아이디어
고객이 말을 멈추면 **두 가지 일을 동시에** 한다. ① 결정 모델(턴 결정기)이 "정말 끝났는지"를 판단하고, ② 그 판단을 기다리지 않고 **답을 미리 만든다**(LLM 선호출 + 첫 문장 음성 선합성). 끝났다고 결정하면 준비된 음성을 바로 보낸다. 끝나지 않았으면(고객이 이어 말하면) 준비한 것을 버린다. 준비물은 **버퍼에만** 두므로 말 끝 전에 소리가 나가는 일은 없다(속도 0점 조건을 구조적으로 차단, 테스트로 확인).

| 시점 (말 멈춘 뒤) | 결정 모델 | 답 준비 |
|---|---|---|
| 200ms 침묵 | 판단 시작(텍스트 유형 9종 × 발화 길이 4구간 표) | 부분 STT로 LLM 선호출, 첫 문장 TTS 선합성 |
| STT 확정 | — | 확정 텍스트가 다르면 선호출 다시 걸기(정규화 비교) |
| 끝 결정(p95 1.11초) | 끝 | 준비된 첫 문장 즉시 송신(약 10ms) |
| 고객이 다시 말함 | 취소 | 선호출·선합성 폐기 |

## 2. 실측 근거
- **속도:** 선준비 + 즉시 송신이 속도 점수를 25.2 → 85.6으로 올렸다(단순 STT+LLM+TTS 대비, 172문항). 시스템 점수 추정 53.1 → 70.7 중 +18이 여기서 나왔다.
- **재사용률:** 선호출 재사용 2/20 → 24/30, 첫 문장 선합성 재사용 14/30(`session_tuning.md`).
- **결정 모델:** 잘못 끊기 42.5% → 15.7%(보정셋 test), 172문항 말 끝 전 응답 55 → 23건, 끝 결정 지연 p95 1.11초.
- **LLM 꼬리:** 동시 요청(500ms) + 컨텍스트 캐시로 첫 응답 p95 3.73 → 1.64초, 첫 마디 뒤 공백 p90 2.2 → 0.2초, 질문당 비용 70% 감소(AG-T15c).

## 3. 검토 의견
1. **방향은 맞다.** 대기(판단)와 생성(LLM·TTS)을 겹치면, 판단에 쓰는 시간(약 1초)이 그대로 답 생성 시간으로 바뀐다. 1.5초 기준에서 가장 큰 효과를 낸 단일 설계다.
2. **약점 ① 채움말 의존.** 지금 85.6점의 상당 부분은 선합성이 아니라 매 턴 캐시 첫 마디("네, 고객님.")가 낸다. 공식 기준은 "모든 응답을 채움말로 시작"을 좋게 보지 않는다(UX 50점). → 선합성 재사용(지금 14/30)을 올려 **준비된 턴은 첫 마디 없이 본 답으로 시작**하고, 준비가 안 된 턴(함수 조회 등)에만 상황별 첫 마디를 쓴다(AG-T20 진행 중).
3. **약점 ② 잘못 끊기의 대가가 크다.** 즉시 송신 구조에서는 잘못 끊으면 곧바로 0점이고 부분 발화로 답하게 된다(말 끝 전 응답 23건 중 16건이 응대 0점). 남은 실패는 대부분 1.1초 넘는 쉼(숫자 묶음 읽기·자기 정정)이다. → 숫자 읽는 중 대기 연장(AG-T15b 진행 중), 끊고 말했더라도 고객이 이어 말하면 즉시 멈추는 바지인(AG-T19)으로 피해를 줄인다.
4. **약점 ③ 함수 문항.** 선준비는 첫 소리만 앞당긴다. 함수 문항 속도는 "조회 결과 → 실제 답" 시간과 평균이므로, 조회 뒤 LLM 재호출(1~3초)이 남는다. → 조회 뒤 첫 문장 즉시 TTS·결과 템플릿(AG-T21 진행 중).
5. **비용·부하.** 버려지는 선호출 비용은 질문당 0.07¢ 수준이라 부담이 작다. 다만 동시 4세션에서 선호출·동시 요청이 겹쳐 호출 한도에 닿지 않는지 확인이 필요하다(AG-T18 부하 시험).

## 4. 결론과 다음 확인
선준비·즉시 서빙은 유지한다. 당일까지의 개선 순서는 **채움말 없이 준비된 답 바로 내보내기(T20) → 긴 쉼 오판 줄이기(T15b)·바지인(T19) → 조회 뒤 지연(T21)**이다. 확인 지표는 선합성 재사용률, 첫 마디 사용률, 말 끝 전 응답 건수, `after_tool_ms`, 첫 소리 p95(≤1.5초)다.

# 03. 사용자 테스트 가이드 — 고객이 되어 상담원과 통화해 보기

> AG-T14. 브라우저 마이크로 우리 상담원 서버(대회 측정기와 같은 프로토콜)에 직접 전화를 거는 로컬 데모다.
> 말한 내용이 어떻게 인식됐는지, 언제 "말이 끝났다"고 판단했는지, 어떤 함수를 불렀는지, 얼마나 빨리 대답했는지를 화면에서 바로 볼 수 있다.
> 가상 쇼핑몰 "다이렉트몰" 기준이다(정책: `cases/manual.md`, 데이터: `mock_api/data/README.md`, 데이터 기준일 2026-11-20 금요일).

## 1. 준비물

| 항목 | 내용 |
|---|---|
| 브라우저 | **크롬 또는 엣지 최신 버전**(AudioWorklet 사용). 사파리·파이어폭스는 확인하지 않았다 |
| 이어폰 | **권장.** 스피커로 들으면 상담원 목소리가 마이크로 다시 들어가 "고객이 또 말했다"로 잡힐 수 있다. 화면의 반이중 옵션(기본 켬)이 상담원이 말하는 동안 마이크를 막아 주지만, 이어폰이 가장 확실하다 |
| 조용한 곳 | 주변 대화·TV 소리도 고객 발화로 잡힌다 |
| API 키 | 프로젝트 폴더의 `.env`에 `GEMINI_API_KEY`(STT·LLM). 상담원 음성은 edge-tts라 키가 필요 없다 |
| 의존성 | `uv sync` 한 번 |

## 2. 실행

### 한 줄 실행 (권장)

PowerShell(기본):

```powershell
powershell -ExecutionPolicy Bypass -File demo\run_demo.ps1
```

Git Bash:

```bash
bash demo/run_demo.sh
```

- Mock API(8100) → 상담원 서버(9000) → 데모 페이지(8080) 순서로 띄우고, 준비되면 브라우저로 **http://127.0.0.1:8080** 을 연다.
- 상담원 서버는 시작할 때 모델 예열(VAD, TTS 캐시 문구 합성, LLM·STT 첫 연결)을 하므로 **20~60초** 걸린다.
- 끝낼 때는 스크립트를 띄운 창에서 **Ctrl+C**. 세 서버를 모두 끄고 포트도 정리한다.
- 이전 실행이 남아 "포트를 이미 쓰는 프로세스가 있습니다"가 나오면 `-Force`(PowerShell) / `--force`(Git Bash)를 붙여 다시 실행한다. 브라우저를 자동으로 열지 않으려면 `-NoBrowser` / `--no-browser`.

### 수동 실행 (창 3개)

```powershell
uv run python -m mock_api.server --port 8100
uv run python -m agent.server --port 9000 --host 127.0.0.1
uv run python -m demo.server --port 8080
```

그다음 브라우저에서 http://127.0.0.1:8080 을 연다. 마이크는 `http://127.0.0.1` 또는 `http://localhost` 주소에서만 허용된다(다른 PC의 IP 주소로 열면 마이크가 막힌다).

## 3. 화면 구성

| 영역 | 위치 | 내용 |
|---|---|---|
| 상단 바 | 맨 위 | **연결 상태**(연결 안 됨/연결 중/연결됨/연결 실패)와 **통화 상태**(듣는 중 / 지금 말하는 중 / 상담원이 답을 준비하는 중 / 상담원이 말하는 중) |
| 통화 설정 | 왼쪽 | **나는 누구인가요?**: 비회원 또는 회원 14명 중 하나. 회원을 고르면 상담원이 내 이름·전화번호를 이미 아는 상태로 통화가 시작된다(실제 측정기의 `caller`). **현재 시각**: 상담원이 "지금"으로 아는 시각(기본 2026-11-20 금 14:00, 영업시간 안). **반이중** 체크(기본 켬, 끼어들기를 시험하려면 끈다), **새 첫 마디 정책** 체크(기본 켬, AG-T20). **통화 시작/종료** 버튼, **마이크 레벨 미터**(회색이면 마이크가 막힌 상태) |
| 이전 대화 | 왼쪽(통화 설정 안) | 통화가 어떤 대화 **다음부터** 이어지는 것처럼 시작하게 하는 패널. 예시 상황 드롭다운 + 줄 편집(상담원/고객, ▲▼✕) + JSON 보기. 자세한 내용은 6절 |
| 내 주문 카드 | 왼쪽 아래 | 회원을 고르면 그 회원의 주문번호·상태·상품이 나온다. 주문번호 밑의 따옴표 글자(예: "이육일일, 일오공, 이삼일")가 상담원이 잘 알아듣는 읽기 방식이다 |
| 대화 기록 | 가운데 | 턴마다 **나**(서버가 최종 인식한 텍스트), **말 끝 판정**(이유·기다린 침묵·발화 길이, 판정 시점 텍스트가 최종과 다르면 함께 표시), **함수 호출**(이름·인자 → 결과 상태, `matched`/`not matched`), **상담원**(실제로 말한 문장 전체), 그리고 👍/👎 + 메모 칸 |
| 응답 속도 | 오른쪽 위 | 큰 숫자 = **내 말 끝 → 상담원 첫 소리**(브라우저에서 잰 값). 1.5초 이하 녹색, 2.5초 이하 노랑, 그 이상 빨강. 아래는 서버가 잰 구간(침묵 시작→판정, 판정→첫 마디, 판정→LLM 첫 응답, 판정→본 응답 첫 소리, 판정→응답 끝, 첫 마디 뒤 공백)과 턴별 기록 |
| 전체 평가 | 오른쪽 아래 | 통화 종료 후 1~5점과 자유 의견 → **피드백 보내기** |

용어:
- **첫 마디**: 말 끝을 판정하자마자 미리 합성해 둔 짧은 문장("네, 고객님." / "네, 확인해 드릴게요." / "네, 불편을 드려 죄송합니다.")을 즉시 보낸다. 대회 속도 점수는 이 첫 소리까지의 시간이다. **새 첫 마디 정책**(AG-T20)을 켜면 답이 이미 준비된 턴은 첫 마디 없이 바로 답하고, 첫 마디를 쓸 때도 상황별 문구를 직전 턴과 겹치지 않게 돌려 쓴다. 대화 기록의 말 끝 판정 줄에 "첫 마디 없음(답이 준비돼 바로 답함)" / "첫 마디 씀(…)"이, 응답 속도 패널에 통화 누적 **첫 마디 사용률**이 나온다.
- **끼어들기(바지인)**: 상담원이 말하는 중에 고객이 0.3초 넘게 말하면 상담원이 말을 멈추고 고객 말을 끝까지 들은 뒤 다시 답한다(AG-T19).
- **본 응답**: 그 뒤 LLM이 만든 실제 답. 첫 마디와 본 응답 사이에 공백이 생길 수 있다.
- **matched**: 함수 서버가 "정답 인자와 정확히 일치"로 본 호출. 대회 함수 점수의 기준이다.

## 4. 체험 절차

1. 왼쪽에서 고객(비회원/회원)과 현재 시각을 고른다.
2. **통화 시작** → 처음 한 번 마이크 권한을 허용한다.
3. 상단이 "연결됨", 대화 기록에 "연결됐습니다. 이제 말해 보세요."가 나오면 평소처럼 말한다.
   - 상담원은 **먼저 인사하지 않는다**(대회 형식: 고객이 먼저 말한다).
4. 말을 마치고 잠시(0.3~1초) 기다리면 상담원이 답한다. 반이중이 켜져 있으면 상담원이 말하는 동안 마이크가 막혀 있다(끼어들기를 해 보려면 S17).
5. 상담원 답이 끝나면 **같은 통화에서 이어서** 말할 수 있다. 앞의 대화를 기억한다.
6. 각 턴에 👍/👎와 메모를 남기고, **통화 종료** 후 점수·의견을 보낸다.

## 5. 체험 시나리오

주문번호는 "이육일일 일오공 이삼일"처럼 **한 자리씩, 3~4자리 묶음으로** 읽으면 가장 잘 알아듣는다. "기대 함수"는 상담원이 불러야 하는 함수이고, 대화 기록의 함수 줄에서 확인한다.

### S1. 영업시간 문의 (기본)

- 설정: 비회원, 기본 시각
- 말해 보기: "영업시간이 어떻게 돼요?" / "토요일에도 상담원이랑 통화할 수 있어요?"
- 기대: 함수 없음. 평일 9시~18시, 점심 12~13시 연결 불가, 주말·공휴일 휴무, 자동 응답은 24시간.
- 관찰: 첫 소리가 녹색(1.5초 이하)인지, 2~3문장으로 짧게 답하는지.

### S2. 배송 조회 — 주문번호 말하기

- 설정: 비회원
- 말해 보기: "주문번호 이육일일 일오공 이삼일이요. 언제 와요?"
- 기대: `track_delivery({"order_id":"2611150231"})` → matched. 배송중, 11월 21일 도착 예정.
- 관찰: "나" 칸에 숫자가 `2611150231`로 맞게 인식됐는지. 틀리면 함수 줄이 `not matched`가 되고 상담원이 번호를 다시 묻는다.

### S3. 회원으로 "제 주문 어디쯤 왔어요?"

- 설정: **김민준**(01023456781) 선택 — 주문 3건(상품준비중 러닝화, 배송중 이어폰, 배송완료 후드티)
- 말해 보기: "제 주문 어디쯤 왔어요?"
- 기대: 전화번호를 다시 묻지 않고 `get_order_list({"phone_number":"01023456781"})`. 주문이 여러 건이면 어떤 주문인지 묻거나 요약한다. 이어서 "이어폰이요"라고 하면 `track_delivery` 2611150231(다중 턴).
- 관찰: 호칭이 "김민준 고객님"인지, 번호를 다시 묻지 않는지.

### S4. 취소 가능한 주문

- 설정: 박지훈(01045678123) — 캠핑 의자 2611190871 결제완료
- 말해 보기: "캠핑 의자 주문 취소해 주세요."
- 기대: `get_order_list` 후(또는 바로) `cancel_order({"order_id":"2611190871"})` → ok, 전액 환불 안내.
- 변형: "취소할까 고민 중이에요" → 취소 실행 없이 조건만 안내해야 한다.

### S5. 취소 불가 주문 (배송중)

- 설정: 비회원
- 말해 보기: "이육일일 일육공 사오칠 주문 취소하고 싶어요."
- 기대: `cancel_order({"order_id":"2611160457"})` → `not_allowed`(matched). 배송중이라 취소 불가, **받은 뒤 반품**하라고 안내.
- 관찰: 거절 이유와 대안을 함께 말하는지.

### S6. 반품·교환

- 설정: 장예린(01098765432)
- 말해 보기: "핸드크림 세트 반품하고 싶어요. 주문번호는 이육일일 일사공 사구팔이요." → 기대 `request_return({"order_id":"2611140498"})` ok, 단순변심 왕복 6,000원 안내.
- 변형: "견과 선물세트도 반품할래요(이육일공 삼공공 이육육)" → 기한(7일) 지남 → not_allowed, 불량이면 상담원 인계 제안.
- 교환: 최수아(01056781234)로 "러닝화 이백오십 사이즈를 이백육십으로 교환하고 싶어요(이육일일 일일공 오구삼)" → `request_exchange`.

### S7. 배송지 변경

- 설정: 이서연(01034567812) — 후드티 2611200105 결제완료
- 말해 보기: "어제 주문한 후드티 배송지를 서울 마포구 월드컵로 백이십으로 바꿔 주세요."
- 기대: `change_shipping_address({"order_id":"2611200105","new_address":"…"})` → ok.
- 변형: 같은 회원의 배송중 주문(스마트워치 밴드 2611160712)으로 바꿔 달라고 하면 not_allowed, 택배사에 직접 요청 안내.

### S8. 상품 재고 — 옵션 별칭

- 설정: 비회원
- 말해 보기: "기모 후드티 엑스라지 사이즈 있어요?"
- 기대: `check_stock({"product_name":"기모 후드티","option":"XL"})` → 품절, 11월 30일 재입고 안내. ("엑스라지" → `XL` 정규화를 보는 시나리오)
- 변형: "스마트워치 밴드 핑크, 아 아니 네이비요. 네이비 재고 있어요?" → option `네이비`(자기 정정 반영).

### S9. 상담원 연결 요청·불만 (영업시간 안)

- 설정: 기본 시각(금 14:00)
- 말해 보기: "그냥 사람이랑 통화할래요." / "벌써 세 번째 전화하는 건데 정말 너무하네요!"
- 기대: 짧은 사과·공감 후 `transfer_to_agent({"reason":"…"})`. 첫 마디가 "네, 불편을 드려 죄송합니다."로 바뀌는지.

### S10. 영업시간 외 콜백 (현재 시각 변경)

- 설정: 회원 아무나(예: 정우진 01067812345), **현재 시각을 2026-11-20 19:30**(또는 토요일 2026-11-21 11:00)으로 바꾼 뒤 통화 시작
- 말해 보기: "상담원이랑 통화하고 싶어요."
- 기대: 지금은 상담 시간이 아니라고 안내하고 `request_callback({"phone_number":"01067812345"})`(caller 번호 사용). `transfer_to_agent`를 부르면 오답.
- 변형: 비회원이면 콜백 번호를 물어야 한다 → "공일공 육칠팔일 이삼사오요"로 답해 보기(다중 턴).

### S11. 범위 밖 질문

- 말해 보기: "내일 서울 날씨 어때요?" / "쿠팡 배송이 더 빨라요?"
- 기대: 함수 없음. 다이렉트몰 업무가 아니라고 정중히 알리고 도울 수 있는 일을 안내. 지어낸 정보가 없어야 한다.

### S12. 턴 감지 함정 — 말 중간에 쉬기

- 말해 보기: "반품을 하려고 하는데요" (1초 쉼) "며칠 안에 해야 돼요?"
- 기대: 쉼에서 끊지 않고 전체 질문에 답하기(7일 이내).
- 관찰: 쉼에서 상담원이 끼어들면 "나" 칸에 앞부분만 남고 말 끝 판정 줄에 짧은 침묵이 보인다. **알려진 한계**: 1.1초가 넘는 쉼, "~요."처럼 완결된 문장 뒤의 쉼은 끊길 수 있다.

### S13. 턴 감지 함정 — 숫자 끊어 읽기

- 말해 보기: "주문번호가 이육일일," (0.7초 쉼) "일구공," (0.7초 쉼) "이삼삼이요."
- 기대: 마지막 묶음까지 듣고 `get_order_info` 또는 `track_delivery`에 `2611190233`.
- 관찰: 묶음 사이 쉼에서 끊기면 1차 리포트의 "말 끝 전 응답" 사례다(남은 손실 중 가장 큰 유형).

### S14. 자기 정정 "아 아니다"

- 말해 보기: "이육일일 일구공 팔칠일 취소요. 아 아니다, 취소 말고 배송지만 바꿀게요. 서울 강서구 공항대로 이백으로요."
- 기대: `cancel_order`를 부르지 않고 `change_shipping_address({"order_id":"2611190871", ...})`만.
- 관찰: 첫 문장 뒤에서 끊기면 취소가 실행될 수 있다(위험 사례로 기록해 주세요).

### S15. 다중 턴 후속 질문

- 설정: 강하은(01078123456)
- 1턴: "텀블러 주문 언제 출고돼요?" → `get_order_list` 또는 `track_delivery` 2611180764(상품준비중, 11월 21일 출고 예정)
- 2턴: "그럼 그거 취소할 수 있어요?" → 앞 대화의 주문을 기억하고 취소 가능하다고 안내(실행은 확인 후)
- 3턴: "네, 취소해 주세요." → `cancel_order({"order_id":"2611180764"})`
- 관찰: 2·3턴에서 주문번호를 다시 묻지 않는지.

### S16. 쿠폰·적립금 (자유)

- 설정: 최수아(VIP, 쿠폰 3장) / 조현우(쿠폰 0장)
- 말해 보기: "쓸 수 있는 쿠폰 있어요?" → `get_coupons(caller 번호)`. 조현우면 "현재 사용 가능한 쿠폰은 없으세요."

### S17. 끼어들기(바지인)·첫 마디 반복 (AG-T19·T20)

- 설정: **이어폰 필수**(스피커면 상담원 목소리가 마이크로 들어가 스스로 끊길 수 있다). **반이중 체크 끄기**, 새 첫 마디 정책 켜기. 고객은 강하은(01078123456) 또는 비회원.
- 1) 정정 끼어들기: "환불 규정 자세히 알려 주세요." → 상담원이 길게 설명하기 시작하면 **1초 이상 들은 뒤** "아니요, 반품 말고 교환이요."라고 끼어든다.
  - 기대: 0.3초 안팎에 상담원 목소리가 멈추고(화면 말 끝 판정 줄에 "끼어들기로 중단 (상담원 말 N초 시점)"), 상담원 칸에는 **실제로 말한 데까지만** 남는다. 내 말이 끝나면 교환 기준으로 다시 답한다. 같은 설명을 처음부터 반복하거나 끼어들기 전 질문에 계속 답하면 실패.
- 2) 추가 질문 끼어들기: "텀블러 주문 언제 출고돼요?" → 답하는 도중 "그거 취소도 돼요?" → 앞의 출고 정보를 기억한 채 취소 가능 여부로 답하는지.
- 3) 맞장구는 무시: 상담원이 말할 때 짧게 "네", "음"(0.3초 미만)만 하면 끊지 않고 끝까지 말해야 한다.
- 4) 첫 마디 반복: 조회 질문을 3번 연달아 해 본다("주문 조회해 주세요" → "다른 주문도요" → "반품 상태도요"). 매 턴 "네, 확인해 드릴게요."만 반복하면 실패. 간단한 질문("영업시간이 어떻게 돼요?" 두 번째부터)은 첫 마디 없이 바로 답하는 턴이 섞여야 한다. 응답 속도 패널의 **첫 마디 사용률**을 메모해 주세요.
- 알려진 동작: 상담원이 말을 **시작한 지 1초 안에** 시작한 말은 끼어들기로 보지 않는다(말 끝을 잘못 판정해 고객이 이어 말하는 경우와 구별하기 위해). 이때는 상담원이 하던 말을 끝낸 뒤 다시 들으니, 잠깐 멈췄다 다시 말해 본다.

## 6. 이전 대화 주입 (history)

> AG-T14b. 대회 측정기는 `session.start`의 `history`에 "이 통화 앞에서 이미 오간 대화"를 넣어 보낼 수 있다(테스트셋의 `followup` 문항). 데모에서도 같은 형식으로 넣어 "상담원이 방금 주문번호를 물었다", "취소할지 확인을 구했다" 같은 상황에서 바로 시작해 볼 수 있다.

### 사용법

1. 왼쪽 **통화 설정 → 이전 대화**에서 **예시 상황**을 고른다. 고르면 그 상황의 **고객(caller)과 현재 시각(now)도 함께 바뀐다.** 설명 상자에 무엇을 시험하는지, "이렇게 말해 보세요" 예문, 기대 함수가 나온다.
2. 필요하면 줄을 고친다. 각 줄은 **상담원/고객** 선택 + 내용, 오른쪽 ▲▼로 순서 이동, ✕로 삭제. **+ 줄 추가**는 마지막 줄과 반대 화자로 빈 줄을 만든다. **비우기**는 프리셋 선택과 줄을 모두 지운다.
3. **JSON으로 보기**를 누르면 서버로 보내는 형식 그대로 고칠 수 있다. **목록으로 보기**를 누를 때 JSON이 틀리면(형식 오류, role 값 오류) 경고를 띄우고 JSON 보기에 머문다.
4. **통화 시작** → 그 내용이 첫 `session.start`의 `history`로 들어간다. 대화 기록 맨 위에 **회색**으로 "주입한 이전 대화 (N줄, 실제 통화 아님)"가 나오고, 그 아래 "— 여기서부터 실제 통화 —" 다음부터가 실제 통화다.
5. 통화 중에는 이전 대화 패널이 잠긴다. 같은 통화 안의 다음 턴은 서버가 스스로 대화를 쌓으므로 다시 보내지 않는다. 다른 상황을 시험하려면 통화를 끝내고 다시 고른다.

보내기 전 검사:

| 검사 | 처리 |
|---|---|
| 내용이 빈 줄 | 빼고 보낸다(경고 문구에 개수 표시) |
| role이 `agent`/`customer`가 아님(JSON 편집 시) | **통화 시작을 막고** 몇 번째 줄인지 알려 준다 |
| 마지막 줄이 고객 말 | **경고만** 하고 그대로 보낸다(실제 측정에서는 마지막이 상담원 말) |

피드백 JSONL에는 `history_preset`(프리셋 id 또는 null)과 실제로 보낸 `history`가 함께 저장된다.

### 직접 작성 요령

- **첫 줄은 고객, 마지막 줄은 상담원 말**로 둔다. 실제 통화처럼 "상담원이 방금 한 말"에 내가 답하는 구조가 된다. 상담원 말이 물음표로 끝나면 서버가 "짧은 대답이 올 것"으로 보고 말 끝 판정을 조금 빠르게 한다.
- 번호는 숫자(`2611150231`)로 적어도, 한글 낭독(`이육일일 일오공 이삼일`)으로 적어도 된다. 서버가 이전 대화의 번호를 모아 "다시 묻지 말고 그대로 쓴다"는 요약을 시스템 프롬프트에 붙인다(고객 줄의 한글 낭독도 인식).
- 회원·주문·상품 이름은 `mock_api/data/README.md` 표와 맞춘다. 데이터에 없는 주문을 지어내면 상담원이 조회해도 not_found가 된다.
- 상담원 줄에는 **이미 안내한 사실**(상태, 금액, 날짜)을 실제 데이터대로 적는다. 틀린 사실을 넣으면 상담원이 그 내용을 믿고 이어서 말할 수 있다.
- 고객(caller)·현재 시각은 이전 대화와 맞게 직접 바꾼다(예: 상담원 줄에 "강하은 고객님"이 있으면 고객도 강하은으로). 영업시간 외 상황은 현재 시각을 18시 이후나 주말로.
- JSON 예:

```json
[
  {"role": "customer", "text": "환불이 언제 되는지 궁금해요."},
  {"role": "agent", "text": "네, 주문번호를 불러 주시겠어요?"}
]
```

## 7. 알려진 한계 (체험 중 이상해 보여도 정상일 수 있음)

| 현상 | 이유 |
|---|---|
| 숫자가 틀리게 인식됨 | STT 숫자 정확도 약 74%(전화 음질 63~68%). 틀리면 함수가 not matched, 상담원이 다시 묻는다. 또박또박 묶어 읽으면 낫다 |
| 말하다 쉬면 상담원이 끼어듦 | 1.5초 안에 답해야 하는 대회 조건 때문에 1.1초 넘는 쉼, 완결처럼 들리는 문장 뒤 쉼은 끊길 수 있다 |
| 첫 마디 뒤 2~5초 공백 | LLM(gemini flash-lite) 혼잡 시 첫 응답이 2.5초를 넘고 대체 모델로 넘어간다. "판정 → LLM 첫 응답" 값으로 확인 |
| 같은 말을 해도 결과가 다름 | LLM·STT는 매번 조금씩 다르다. 재현이 필요하면 같은 문장으로 2~3번 시도해 기록 |
| 끼어들어도 상담원이 안 멈춤 | 반이중이 켜져 있으면 상담원이 말하는 동안 마이크가 막혀 끼어들기가 서버에 닿지 않는다(S17처럼 끄고 이어폰 사용). 상담원 첫 소리 1초 안에 시작한 말, 0.3초 미만의 짧은 말은 일부러 무시한다 |
| 스피커로 들으면 상담원이 혼자 멈춤 | 반이중을 끈 상태에서 브라우저 에코 제거가 상담원 목소리를 다 지우지 못하면 그 소리를 끼어들기로 본다. 이어폰을 쓴다 |
| 브라우저 잡음 억제 | 브라우저의 잡음 억제·자동 음량이 켜져 있어 측정기 음성과 소리가 조금 다르다. 쉼 길이가 미세하게 달라져 판정이 달라질 수 있다 |
| 첫 소리 시간 | 브라우저 값은 "내 마이크 에너지가 마지막으로 컸던 시점 → 상담원 첫 유성음 도착"이다. 대회 채점(정답 말 끝 시각 기준)과 수십~수백 ms 차이가 날 수 있다 |

## 8. 피드백 남기기

- 턴마다 👍/👎와 메모(예: "번호를 잘못 알아들음", "말 중간에 끊김", "답이 너무 김").
- 통화 종료 → 1~5점 + 자유 의견 → **피드백 보내기**. 
- 저장 위치: `runs/demo_feedback/feedback-YYYYMMDD.jsonl`(한 통화 한 줄). 대화 텍스트, 말 끝 판정, 함수 호출·matched, 첫 소리 시간, 서버 구간 시간, 투표·메모가 함께 들어 있어 그대로 분석에 쓸 수 있다.
- 서버 쪽 상세 로그는 `runs/logs/turns-YYYYMMDD.jsonl`(턴마다 한 줄, session_id가 `DEMO-…`로 시작)에 남는다. 피드백의 `session_id`로 찾을 수 있다.
- 문제를 알릴 때는 **시나리오 번호, 실제로 한 말, 화면의 "나" 텍스트, 함수 줄, 응답 속도 값**을 같이 적어 주면 재현이 쉽다.

## 9. 문제 해결

| 증상 | 확인 |
|---|---|
| "포트를 이미 쓰는 프로세스가 있습니다" | 이전 데모가 남은 것. `-Force`/`--force`로 다시 실행하거나 `Get-NetTCPConnection -LocalPort 9000 -State Listen`으로 PID 확인 후 종료 |
| 상담원 서버가 준비되지 않음 / 바로 종료 | `runs/logs/demo_agent.err.log` 확인. `GEMINI_API_KEY`가 `.env`에 있는지, `uv sync`를 했는지 |
| "상담원 서버에 연결할 수 없습니다" | 스크립트 창에 "준비 완료"가 떴는지(예열 중이면 기다림). 수동 실행이면 9000 서버가 떠 있는지 |
| 마이크를 쓸 수 없음 | 주소가 `http://127.0.0.1:8080`인지(IP 주소 금지), 주소창 왼쪽 자물쇠 → 마이크 허용, 윈도우 설정 → 개인정보 → 마이크 → 앱 접근 허용, 다른 앱이 마이크를 독점하지 않는지 |
| 레벨 미터가 안 움직임 | 윈도우 사운드 설정에서 입력 장치 확인. 미터가 회색이면 상담원 차례(반이중)라 막힌 것 |
| 말해도 반응 없음 | 미터가 충분히 올라가는지(마이크 가까이). 대화 기록에 아무것도 안 생기면 `runs/logs/demo_agent.err.log` |
| 상담원 목소리가 안 들림 | 브라우저 탭 음소거, 출력 장치 확인. 탭을 한 번 클릭한 뒤 다시 시작 |
| 상담원이 자기 목소리에 반응 | 반이중 체크가 켜져 있는지, 이어폰 사용 |
| 함수 줄에 matched 표시가 없음 | Mock API(8100)가 꺼져 있으면 matched를 못 가져온다. 함수 호출 자체도 실패한다 |

로그 위치: `runs/logs/demo_mock.log`, `demo_agent.log`, `demo_web.log`(+ `.err.log`), 턴 로그 `runs/logs/turns-YYYYMMDD.jsonl`.

## 10. 비용 감각

- 통화 1턴(고객 발화 1회 + 응답 1회)에 약 **$0.003~0.005**(Gemini LLM 입력이 대부분 — 매뉴얼·함수 정의가 매번 들어간다, 실시간 STT 1분 $0.009 수준). 상담원 음성(edge-tts)과 VAD는 무료.
- 30분 동안 50턴을 체험해도 약 $0.15~0.25. 다중 턴은 대화가 길어질수록 입력 토큰이 늘어 턴당 비용이 조금씩 오른다.
- 정확한 금액은 Cloud 결제 콘솔에서 확인(반영에 최대 하루).

## 11. 참고 — 데모가 서버에 보내는 것

- 브라우저가 상담원 서버에 직접 WebSocket으로 붙는다: `session.start`(session_id `DEMO-…`, now, caller, history(이전 대화 패널 내용, 없으면 `[]`), tools_url, **`"debug": true`**, `"barge_in": true`, `"opener_adaptive": true|false`(새 첫 마디 정책 체크)) → 16kHz s16le 20ms(640바이트) PCM 프레임(실시간).
- `"debug": true`일 때만 서버가 `debug.turn`(speech_start/silence/resume/decided), `debug.stt`, `debug.tool`, `debug.timing`(첫 마디 사용 여부·이유·`opener_rate`, 끼어들기 여부 포함), `debug.barge_in`(끼어들기 감지: `late`, `heard_ms`, `voiced_ms`) 텍스트 이벤트를 더 보낸다. 브라우저는 `debug.barge_in`을 받으면 예약된 상담원 음성을 즉시 멈춘다. 측정기는 이 필드를 보내지 않으므로 측정기 메시지는 같다(`tests/test_session_debug.py`, `tests/test_barge_in.py`).
- 끼어들기 때도 프로토콜은 그대로다: 그 턴의 `agent.transcript`(실제로 말한 데까지) → `turn.end`, 그다음 끼어든 말을 새 턴으로 듣고 답한다. 끊을 수 있게 서버는 응답 오디오를 재생보다 1.5초 넘게 앞서 보내지 않는다(확정 뒤 10초까지).
- 함수 matched는 데모 서버의 `/api/calls`(Mock API `/calls` 프록시)로 턴이 끝날 때 가져온다.

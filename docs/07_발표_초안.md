## 1. 제목 (15초)

- **핵심 메시지**: 말이 끝나기 전에 답을 준비하는 한국어 음성 상담원.
- **화면**: 팀명 Directon / 한 줄 소개 / "172문항 실측 기반 설계"
- **노트**: "저희는 고객이 말을 마치는 순간 이미 답이 준비돼 있는 상담원을 만들었습니다. 오늘 말씀드릴 모든 결정은 직접 만든 172문항 측정으로 골랐습니다."

## 2. Problem & Goal — 상담원이 실패하는 두 순간 (45초)

- **핵심 메시지**: 너무 늦게 답하거나, 말 중간에 끼어든다. 한국어는 둘 다 쉽게 일어난다.
- **화면**:
  - 예시 발화 파형: "주문번호가요 … 이육일일 … 일오공 …" (쉼 위치 표시)
  - 고정 침묵 800ms 단순 조합: 첫 소리 p50 **5.16초**, 1.5초 안에 답한 문항 172개 중 **8개**
  - 목표: ① 1.5초 안에 첫 소리 ② 말 끝 전에는 절대 소리 안 냄 ③ 번호·상품명을 정확히 함수에 ④ 사람이 필요하면 바로 넘김
- **노트**: "한국어 고객은 조사·연결어미·숫자 묶음 뒤에서 자주 쉽니다. 기다리면 느리고, 끊으면 끼어듭니다. 흔한 방식대로 만들면 첫 소리가 5초 걸렸습니다. 건강기능식품 쇼핑몰이라는 도메인에서는 여기에 '몸이 불편하다'는 문의를 사람에게 정확히 넘기는 일이 더해집니다."

## 3. System Architecture — 말이 끝나기 전에 준비한다 (60초)

- **핵심 메시지**: 듣기 → 판단 → 미리 준비 → 즉시 말하기 → 업무 처리, 다섯 부품.
- **화면**: 파이프라인 그림 + 시간축
  - STT `gemini-3.5-transcribe-live` / VAD Silero / 보정 턴 결정기
  - 침묵 200ms → LLM 선호출 + 첫 문장 선합성(송신 안 함)
  - 확정 → **약 10ms** 뒤 첫 소리
  - LLM `gemini-3.5-flash-lite` + 500ms 뒤 `3.1-flash-lite` 동시 요청 + 컨텍스트 캐시
  - 함수 14개(`X-Session-Id`), 한국어 숫자·별칭·주문번호 정규화
  - TTS edge-tts(+대체)
- **노트**: "핵심은 3번, 미리 준비입니다. 고객이 0.2초 멈추면 그 순간의 받아쓰기로 LLM을 먼저 부르고 첫 문장 음성까지 만들어 둡니다. 말 끝이 확정되면 최종 문장과 비교해 같으면 그대로 씁니다. 재사용률은 20번 중 2번에서 30번 중 24번으로 올랐습니다. LLM은 빠른 모델이 0.5초 안에 응답을 시작하지 않으면 예비 모델에도 같이 보내, 느린 꼬리를 3.7초에서 1.6초로 잘랐습니다."

## 4. System Architecture — 말 끝 판단 (45초)

- **핵심 메시지**: 소리만으로는 쉼과 말 끝을 구분할 수 없었다. 문장 끝 모양과 발화 길이로 대기 시간을 정한다.
- **화면**:
  - 변별력(AUC): Smart Turn(음성 모델) **0.57** / 텍스트 규칙 **0.83** / 텍스트 + 발화 길이 **0.894**
  - 표 예시: "연결어미·조사·숫자 묶음·자기 정정·쉼표로 끝남 → 최대 2초", "질문·완결 → 짧게", 그 밖 상한 1.3초
  - 보정셋 771발화(쉼 위치 자동 라벨, 화자·문장 비중복)
  - 잘못 끊기(보정셋 test): 42.5% → 15.7%(1차) → 2차 보정 10.1%(확장 test 228)
- **노트**: "공개 음성 턴 모델은 한국어 통화 음성에서 거의 동전 던지기였습니다. 그래서 쉼 위치를 알고 합성한 771개 발화로 직접 보정했습니다. '이육일일'처럼 숫자 묶음에서 멈추면 더 기다리고, '언제 와요?'처럼 끝나면 빨리 답합니다."

## 5. AI Scope & Human Handoff (45초)

- **핵심 메시지**: AI는 안내와 함수 선택, 규칙은 타이밍과 정규화, 사람은 판단이 필요한 일.
- **화면**:
  - 인계 기준 6가지: ① **섭취 후 몸 불편·의료 질문** ② 직접 요청 ③ 욕설·강한 불만 ④ 세 번 이상 이해 실패 ⑤ 법적 문제(소송·개인정보·부상) ⑥ 매뉴얼 밖 예외
  - 인계는 말이 아니라 `transfer_to_agent` 함수 호출로. 영업시간 외에는 콜백 접수
  - 안전망: "연결해 드릴게요"라고 말하고 함수를 안 부르면 자동 호출
  - 불만·인계 범주 함수 일치(오프라인) **0.12 → 0.88**
- **노트**: "건강기능식품에서 '먹고 나서 두드러기가 났다'는 질문에 AI가 답하면 위험합니다. 이런 문의는 사과 한 문장 뒤 바로 사람에게 넘기고, 사유를 한 줄로 남깁니다. 처음에는 LLM이 '연결해 드릴게요'라고 말만 하고 실제 연결을 안 했는데, 규칙과 안전망으로 고쳤습니다."

## 6. Speed vs. Quality (50초)

- **핵심 메시지**: 1.5초 안이면 만점이므로, 남는 시간을 "끼어들지 않기"에 썼다.
- **화면** (표 4줄):
  - 대기: 진짜 말 끝 지연 p50 677 → 816ms로 늘리고, 말 끝 전 확정 28 → 13(시뮬레이션)
  - 첫 소리: 답이 준비되면 첫 마디 없이 바로 답, 아니면 상황별로 다른 짧은 첫 마디(같은 채움말 반복 금지) 〔당일 확인: AG-T20〕
  - 번호: 자릿수가 틀린 번호는 함수에 보내지 않음 → 고객 주문 목록으로 교정, 안 되면 짧게 되묻기
  - 모델: 빠른 모델 우선 + 0.5초 뒤 예비 모델 → 공백 p90 2.2초 → 0.2초, 비용 70% 절감
- **노트**: "속도 점수는 0.5초 단위라 0.3초 더 빠르게 해도 점수가 거의 안 오릅니다. 반면 한 번 끼어들면 그 문항은 0점이고 고객 경험도 망칩니다. 그래서 기다릴 이유가 있는 문장에서는 더 기다립니다. 그리고 모든 답을 '네, 고객님'으로 시작하는 건 점수만 위한 설계라, 답이 준비됐으면 바로 답하게 바꾸고 있습니다(〔당일 결과로 문장 확정〕)."

## 7. Demo (70초)

- **핵심 메시지**: 끊어 읽는 주문번호도 기다렸다가 바로 조회해 답한다. 몸이 불편하다면 사람에게 넘긴다.
- **화면**: 라이브 또는 녹화(브라우저 마이크 데모, `demo/`). 화면 오른쪽에 턴 로그(확정까지 대기, 첫 소리 시각, 호출 함수).
  - 시나리오 A(30초): "주문번호가요 … 〔당일 공식 번호 형식〕 … 언제 와요?" → 배송 조회
  - 시나리오 B(20초): "어제 받은 거 먹고 속이 안 좋아요" → 사과 + 상담원 연결
  - 시나리오 C(20초, 바지인 완성 시): 상담원 답 도중 "아 아니, 취소 말고 교환이요" → 멈추고 다시 응대 〔당일 확인〕
- **노트**: 네트워크 장애 대비 녹화본을 미리 준비. 라이브는 A만, B·C는 녹화로 보여도 된다.

## 8. Evaluation Result (50초)

- **핵심 메시지**: 같은 172문항·같은 측정기에서 단순 조합 대비 속도 25.2 → 85.6.
- **화면**:
  - 평가 방법 한 줄: 172문항(범주 7종, 화자 11종, 채널 3종·잡음 5종·SNR 4단계·음량·패킷 손실·말 속도) + 턴 보정셋 771발화 + LLM judge + 단순 조합 기준선
  - 표:

    | | 단순 조합 | 1차(round1) | 2차(round2) |
    |---|---|---|---|
    | 속도 점수 | 25.2 | 85.6 | 〔당일 측정〕 |
    | 1.5초 안 첫 소리(만점) 문항 | 8 | 138 | 〔당일 측정〕 |
    | 함수 점수 | 65.7 | 74.4 | 〔당일 측정〕 |
    | 응대(judge) | 64.8 | 60.4 | 〔당일 측정〕 |
    | 시스템 점수 추정 | 53.1 | 70.7 | 〔당일 측정〕 |

  - 공식 연습 문항: 〔당일 측정〕 / 조회 뒤 답까지 시간: 〔당일 측정〕
- **노트**: "1차에서 응대 점수는 오히려 단순 조합보다 낮았습니다. 원인을 세 가지로 나눴고, 다음 장에서 말씀드리겠습니다."

## 9. Failure / Improvement (40초)

- **핵심 메시지**: 실패를 수치로 나누고, 하나씩 고쳤다. 남은 한계도 숫자로 안다.
- **화면**:
  - 실패 1: 빨리 답하려다 말 끝 전에 답함 55건 → 23건 → 2차 보정 시뮬레이션 13건
  - 실패 2: "번호를 한 자리씩 다시" 되묻기 16건 → 조건부 완화 + 고객 주문 목록 교정, judge 58.9 → 65.3
  - 실패 3: LLM 혼잡으로 첫 마디 뒤 2초 넘는 침묵 → hedge + 캐시로 공백 p90 0.2초
  - 남은 한계: 1.4초 넘는 쉼, 전화 채널 숫자 인식 68~71%, 합성음 테스트셋 → 바지인, 공식 음성 재보정
- **노트**: "끼어든 문항은 응대 점수까지 0점이 됐습니다. 숫자 오인식을 막으려던 되묻기는 정작 안내를 빠뜨렸습니다. 모두 측정으로 찾았고 측정으로 확인했습니다. 감사합니다."

듣기 (STT)

당일 교체

고객 음성을 실시간으로 글자로 바꿉니다. 말하는 도중에도 부분 결과를 내서 뒤 단계가 일찍 움직이게 합니다.

동작
session.start를 받자마자 STT 연결을 엽니다(연결 약 0.37초를 미리 씀). 20ms 프레임을 100ms씩 묶어 보내고 부분 결과를 계속 받습니다. 200ms 쉼이 생기면 finalize를 보내 최종 텍스트를 받습니다. 부분 결과에서 숫자가 사라지는 경우를 되살리는 래퍼(DigitRecheckSTT)를 씁니다. 일괄 재인식은 효과가 없어 껐습니다.
왜
일괄 STT는 2.2~10.9초가 걸려 1.5초 예산에 들어가지 않습니다. 부분 결과가 있어야 말 끝 판단과 LLM 선호출을 쉼 200ms 시점에 시작할 수 있습니다.
측정
finalize → 최종 텍스트 p50 0.40~0.43초. 글자 오류율(숫자 정규화 후) 0.065. 숫자 정확도 74%(54문항 중 40), 전화 채널 63~68%. 묶음 크기, 재인식, 설정을 바꿔도 숫자 정확도는 오르지 않았습니다.
한계
4자리 번호에서 앞자리 "일"을 빠뜨립니다("일삼공이" → 130). 장애 구간에 실시간 연결이 31회 실패했습니다.
당일 모델

A2 · 처리 단계

말 끝 판단 (텍스트 규칙 + 보정한 대기표)

재보정 필요

고객이 멈췄을 때 "말을 마쳤다"고 판단하는 시점을 정합니다. 속도 점수의 0점 조건이 여기서 갈립니다.

동작
로컬 Silero VAD(20ms를 512샘플로 다시 잘라 넣음)가 무음 길이를 잽니다. 무음이 200ms를 넘으면 그 순간 STT 텍스트의 끝을 손으로 쓴 규칙으로 13개 묶음에 나눕니다(종결어미, 질문, 단답, 완결 숫자, 연결어미, 간투사, 조사, 숫자 미완, 자기 정정, 쉼표 끝 등). 그다음 (묶음 × 지금까지 말한 길이 4구간) 표에서 대기 시간을 찾아, 무음이 그보다 길어지면 확정합니다. 일반 상한은 1.3초이고, 연결어미·간투사·조사·정정·쉼표 끝은 2초까지 기다립니다. 직전 상담원 말이 질문이면 단답을 예상해 100ms 줄입니다.
왜
1.5초 안이면 모두 만점이라 빨리 끊을 이유가 없고, 일찍 끊으면 0점입니다. 그래서 "1.5초 안에서 잘못 끊기 최소"를 목표로 잡았습니다. 오디오 모델 Smart Turn v3.2는 한국어 통화 음성에서 쉼과 말 끝을 구분하지 못해(AUC 0.57) 결정에서 뺐습니다.
측정
표의 값은 데이터로 골랐습니다. 목표는 잘못 끊기 최소, 조건은 진짜 말 끝 지연 p95 ≤ 1.3초와 놓침 증가 ≤ 1%p였고, 칸마다 값을 바꿔 가며 찾았습니다. 보정셋 test 잘못 끊기 19.7 → 10.1%, 172문항 실측 말 끝 전 발화 55 → 23 → 11건, 진짜 말 끝 지연 p95 1.29초.

200ms 쉼에 부분 결과로 LLM을 미리 부릅니다. 확정 전에 finalize가 끝나 텍스트가 달라졌으면 다시 겁니다. 확정 뒤 최종 텍스트와 선호출 텍스트를 정규화(한글 숫자를 숫자로, 공백·부호 제거)해 같으면 선호출 결과를 그대로 씁니다. LLM 스트림에서 첫 문장이 나오면 음성도 미리 받아 둡니다. 확정 전에 고객이 다시 말하면 모두 취소합니다.
왜
판단 대기(최대 1.3초)와 LLM 첫 응답(약 1초)을 겹치면, 확정 순간 답이 거의 준비됩니다.
측정
선호출 재사용 2/20 → 24/30. 단순 조합 대비 속도 25.2 → 85.6의 대부분이 첫 마디 캐시와 함께 여기서 나왔습니다. 준비된 첫 문장은 확정 뒤 약 10ms에 나갑니다.
한계
고객이 말을 이으면 만든 호출을 버립니다(질문당 약 0.07¢). 말 끝을 잘못 판단하면 끊긴 문장에 바로 답합니다(round1 말 끝 전 발화 23건 중 16건이 응대 0점).
당일 모델
GPT-5.4 mini의 첫 응답 지연이 다르면 재사용률이 바뀝니다. TTS가 2.56초 걸리면 첫 문장 선합성이 확정 시점까지 거의 끝나지 않아 첫 마디 뒤 공백이 늘어납니다. 첫 문장을 짧게 끊는 것이 대책입니다.

첫 마디 (녹음해 둔 짧은 문장)

켬

말 끝을 확정한 순간 미리 합성해 둔 짧은 문장을 보냅니다. 속도 점수는 사실상 이 소리의 도착 시각으로 정해집니다.

동작
서버를 켤 때 첫 마디·채움말·사과 문장을 합성해 메모리에 올립니다(assets/tts_cache/). 앞 무음을 잘라 첫 프레임부터 유성음 기준(RMS 300)을 넘깁니다. 텍스트로 고릅니다. 불만 표현이면 "네, 불편을 드려 죄송합니다.", 조회·처리 표현이나 4자리 이상 숫자면 "네, 확인해 드릴게요.", 그 밖은 "네, 고객님."입니다. LLM에는 "이미 이렇게 말했다"고 알려 자연스럽게 잇게 합니다. 정책 스위치를 켜면 직전 턴과 같은 첫 마디와 채움말을 쓰지 않고, 답이 이미 준비돼 있으면 첫 마디를 생략합니다.
왜
본 응답 경로(STT 0.43 + LLM 0.8~1.3 + TTS 0.47초)는 p50만 1.7~2.2초라 1.5초 안에 들어오지 않습니다. 첫 소리만 빠르면 되는 채점 규칙을 이용했습니다.
측정
첫 소리 p50 0.83초, 1.5초 안 147/172문항. 첫 마디 사용률 100%. 확정 순간 답이 준비된 턴이 0회라 "생략"은 한 번도 일어나지 않았습니다.
한계
공식 기준은 "모든 응답을 채움말로 시작"을 좋게 보지 않습니다. 시험지가 단일 턴이라 반복 금지 효과는 재지 못했고, 데모에서 사람이 확인해야 합니다.
당일 모델
캐시 문장을 Gemini 2.5 Flash TTS의 같은 목소리로 다시 합성해야 첫 마디와 본 응답 목소리가 섞이지 않습니다. 첫 마디가 녹음본이라 TTS가 느려도 속도 점수는 지킬 수 있습니다. 대신 TTS가 느린 만큼 첫 마디를 조금 길게, 종류를 많이 두는 것을 검토합니다.

조회 (함수 호출과 인자 고치기)

당일 데이터 교체

LLM이 고른 함수를 Mock API에 부릅니다. 함수 점수는 이름과 인자가 정확히 맞아야 나오므로, 인자를 세 겹으로 고칩니다.

동작
세션 시작 때 GET /tools로 함수 정의를 받아 LLM에 줍니다. LLM이 함수를 고르면 (1) 정규화: 한국어 숫자 읽기("공일공 일이삼사"), 영문 철자, 전화번호 하이픈, 날짜(now 기준)를 고칩니다. (2) 카탈로그: 상품명·옵션 별칭을 맞춥니다(엑스라지 → XL, 회색 → 그레이). 후보가 하나일 때만 바꿉니다. (3) 번호 교정: 고객이 실제로 말한 번호와 대조해 LLM이 잘못 옮긴 자리를 고치고, 자릿수가 틀리면 발신 고객의 주문 목록에서 가장 가까운 번호를 찾습니다. 모든 호출에 X-Session-Id를 붙입니다. 응답이 "상담원에게 연결해 드릴게요"라고 약속했는데 인계 함수를 부르지 않았으면 자동으로 부르는 안전망도 있습니다.
왜
STT 숫자 정확도가 74%에 그쳐, 인자를 그대로 넘기면 함수 점수를 크게 잃습니다.
측정
함수 점수 56.4 → 80.8, 완전 일치 0.52 → 0.77(실서버). 카탈로그만 따로 보면 상품 21문항 0.71 → 0.79. 정답 텍스트로 잰 오프라인 평가는 0.72 → 0.90.
한계
발신 번호로 고객을 알면서 목록 조회부터 부르는 경우 약 12건, 지나치게 되묻는 경우 약 8건, STT 숫자 오인식 약 6건.
당일 모델

동작

왜

켬

동작

조회 결과 템플릿

켬

조회 결과가 오면 LLM을 기다리지 않고, 결과에 적힌 사실로 만든 첫 문장부터 말합니다.

동작
함수 결과에 있는 고객용 상태 문장("주문이 취소되었습니다.", "배송중입니다.")으로 첫 문장을 만들어 바로 말합니다. 숫자는 넣지 않고, 확실하지 않으면 말하지 않습니다. LLM에는 이미 말한 문장을 알려 반복을 피하게 하고, 그래도 반복하면 그 문장을 지웁니다.
왜
함수 문항의 공식 속도는 (말 끝 → 첫 소리)와 (조회 결과 → 실제 답) 점수의 평균입니다. 뒤쪽은 템플릿 말고는 1초 아래로 내린 방법이 없었습니다.
측정
조회 뒤 실제 답 p50 2.33 → 0.99초(R2-best 0.94초). 측정기 기준 p95 2.29 → 1.02초로 모든 함수 문항이 100점 구간. 공식 속도(채움말 제외) 85.7 → 89.4. LLM 비용 변화 없음.
한계

당일 모델

Jev 말 끝 판단

당일 A/B로 결정

표 결정기 위에 Jev의 "말을 마쳤나" 판단을 얹습니다. 결정은 표가 하고, Jev는 대기 시간만 조정합니다.

동작
200ms 쉼에 지금까지의 말, 이전 대화 전체(개수 제한 없음), 발신자 정보 여부를 보내고 세 가지를 묻습니다. 말을 마쳤나, 문장·숫자 중간에서 끊겼나, 곧 더 말할 것 같나. "마쳤다"가 0.3 이하이면 대기를 상한까지 늘립니다. 대기를 줄이는 쪽은 꺼 두었습니다(1초 안쪽은 줄여도 점수 이득이 없음). 0.6초 안에 답이 없으면 표대로 갑니다.

한국어 테스트셋 합성

데모 음성은 영어 3개뿐이어서, 한국어 시험지를 직접 만들었습니다.

동작
시나리오(cases.jsonl)마다 발화를 쉼 단위로 나눠 적고, 여러 TTS 음성(Gemini 8, edge 3)으로 합성해 이어 붙입니다. 그 위에 통화 환경을 입힙니다. 채널 3종(광대역·전화·μ-law), 잡음 5종(white·pink·웅성거림·60Hz 험·없음), SNR 4단계, 음량 3단계, 20ms 패킷 손실, 말 속도 3단계입니다. 말 끝 시각(speech_end)은 20ms 오차로 계산하고, 합성 결과는 해시로 캐시합니다.
결과

한계

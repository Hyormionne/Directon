### 최종 평가·제출 규칙 (README 7장)

- 18:30까지 **압축 파일 하나**를 낸다. 맨 위 폴더에 `start_server.sh`, `start_mock.sh`, `requirements.txt`, 필요하면 `.env`를 둔다.
- 운영진은 팀별 컨테이너(리눅스, **Python 3.11**, ffmpeg 있음, 인터넷 됨, GPU 없음)에서 `pip install -r requirements.txt` → `bash start_mock.sh <mock_db_test.json>` → `bash start_server.sh` 순서로 띄운다. **`.venv`는 넣지 않는다.** `uv`가 아니라 `pip`로 설치한다.
- **설치나 시작이 안 되면 그 팀 문항은 모두 0점이다.** 제출 전에 새 폴더에 풀고 새 가상환경에서 `--limit 5`가 도는지 확인하라고 한다.
- API 키는 `.env`에 넣어 같이 낸다. 측정에 쓸 크레딧을 남겨 둔다.
- 제출 뒤에는 코드를 바꿀 수 없다. 측정 때 팀 노트북은 필요 없다(터널 불필요).
- 시험 문항은 연습과 다른 손님, 더 최근 날짜에서 뽑는다. 시나리오와 브랜드 정보는 연습과 같다.
- `X-Session-Id`가 빠진 호출은 **호출하지 않은 것으로** 본다.
- 시스템 총점이 0.5점 이내로 같으면 응대 점수가 높은 팀이 앞선다.

## 3. 채점 방식 (`eval/score.py`)

- 총점 = 응대 × 0.5 + 함수 × 0.2 + 속도 × 0.3 (각 100점). 대회 최종 점수에서는 이 값이 20점 몫이다(`04_목표_점검.md`).
- **응대:** 답 음성을 `gpt-4o-transcribe`로 받아쓰고, `gpt-5.5`(reasoning low)가 `scenarios.md` + `information.json` 전체 + 대화 + 실제 상담 답을 보고 맞음 1.0 / 괜찮음 0.7 / 틀림 0으로 판정한다.
  - 감점하지 않는 것: 링크를 안 읽음, 짧은 문장, 인사말 생략, 채움말
  - 틀림: 사실 오류, 필요한 확인 생략, 함수를 불러야 할 때 안 부름, **정보 없이 부름**, 상담원 연결 판단을 잘못함(양쪽 다)
- **함수(`tool_match`):**
  - `search_products`는 함수 점수에서 뺀다(응대 판정에서만 본다).
  - 정답 호출은 모두 해야 하고, 번호 인자(`order_id`, `buyer_cellphone`, `customer_phone_number`, `phone_number`, `order_number`)의 **숫자**가 정답과 같아야 한다.
  - 조회 함수(`get_order_info`, `get_return_info`)를 더 부르는 것은 괜찮다. history에 같은 조회 결과가 있으면 안 불러도 된다.
  - **정답에 없는 접수 함수**(취소·반품·교환·콜백)를 부르면 틀림.
- **속도:** 첫 소리 표는 Starter Kit과 같다(1.5초 이하 100). 함수 문항은 첫 소리 점수와 조회 뒤 답 점수(3.5초 이하 100, 4.0 → 90 … 8.0 → 10)의 평균. 말 끝 전 소리는 0점.

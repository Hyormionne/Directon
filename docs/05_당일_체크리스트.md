## 1. 09:00 자료 받기 (~10분)

공식 자료를 `official/`에 저장한다. 파일 이름은 아래로 맞춘다.

| 자료 | 저장 위치 | 쓰는 곳 |
|---|---|---|
| 응대 매뉴얼 | `official/manual.md` (PDF·docx면 텍스트로 옮겨 붙인다) | `DIRECTON_MANUAL` |
| 함수 정의 | `official/tools.json` | Mock `--tools` → 상담원은 `GET /tools`로 받음 |
| Mock 데이터 | `official/mock_data.json` | Mock `--data`, 카탈로그·번호 자릿수 |
| 브랜드 소개(있으면) | `official/brand.md` | `DIRECTON_BRAND` |
| 말투 가이드(있으면) | `official/style.md` | `DIRECTON_STYLE` |

- [ ] JSON이 열리는지: `uv run python -c "import json;json.load(open('official/tools.json',encoding='utf-8'));json.load(open('official/mock_data.json',encoding='utf-8'))"`
- [ ] 함수 정의 형식: `[{name, description, parameters}]`와 `[{"type":"function","function":{...}}]` 둘 다 읽는다
- [ ] 데이터 형식: 우리 쇼핑몰 형식(members·orders·products …) 또는 Starter Kit 매핑 형식(`{함수명: [{"arguments":…, "result":…}]}`). 그 밖의 형식이면 매핑 형식으로 변환하는 스크립트를 먼저 만든다

## 2. 교체 (~5분, 코드 수정 없음)

```bash
export DIRECTON_MOCK_DATA=official/mock_data.json   # Mock·카탈로그·번호 자릿수가 같이 따라간다
export DIRECTON_MOCK_TOOLS=official/tools.json
export DIRECTON_MANUAL=official/manual.md
export DIRECTON_BRAND=official/brand.md             # 없으면 지정하지 않는다
export DIRECTON_STYLE=official/style.md             # 없으면 지정하지 않는다

uv run python -m mock_api.server --port 8100        # 시작 줄에 tools 수, shop/mapping, 경로가 찍힌다
uv run python -m agent.server --port 9000           # 다른 터미널, 같은 환경변수
```

- [ ] Mock 시작 줄의 함수 개수가 공식 정의와 같다
- [ ] 번호 자릿수 확인: `uv run python -c "from agent.catalog import order_id_lengths,phone_lengths;print(order_id_lengths(),phone_lengths())"` → 공식 데이터의 주문번호 길이(예: `frozenset({4})`)
- [ ] 프롬프트 확인: `uv run python -c "from agent.prompts import fixed_prompt;print(fixed_prompt())" | grep 자리` → 그 자릿수로 적혀 있다
- [ ] 우리 쇼핑몰 함수 이름(get_order_info 등)과 공식 이름이 다르면, 프롬프트의 함수 이름 규칙(`agent/prompts.py` 고정부)은 공식 이름으로 맞춰야 한다 → 이 경우만 코드 수정(트랙 문서에 기록)

## 5-1. Jev 스위치 A/B (~50분, 사용자 결정 2026-11-20: 당일 데이터를 받은 뒤 벤치마크로 결정)

`DIRECTON_JEV_TURN`(말 끝 판단)과 `DIRECTON_JEV_HANDOFF`(사람 인계 판단)를 켤지 여기서 정한다. 현재 R2-best는 인계만 켜고 말 끝은 끈 상태다.

미리 확인:
- [ ] 운영진: 당일 모델(Soniox STT · Gemini 2.5 Flash TTS · GPT-5.4 mini) 외에 Jev(TypeSafe)를 써도 되는지. **안 되면 A/B 없이 둘 다 끈다**
- [ ] `.env`에 `TYPESAFE_API_KEY`가 있는지(값은 보지도 붙이지도 않는다), TypeSafe 대시보드에서 Jev 단가 확인
- [ ] 모든 arm을 당일과 같은 Provider 설정·같은 시간대로 연달아 돌린다(외부 API 혼잡이 arm 차이로 보이지 않게)

실행(arm당 약 11분, 172문항, `runs/round2/run.sh`는 git 추적 밖 로컬 파일):

```bash
B="DIRECTON_TOOL_TEMPLATE=1 DIRECTON_OPENER_ADAPTIVE=1"      # R2-best에서 Jev만 뺀 공통 바탕
JUDGE=1 bash runs/round2/run.sh D-base     $B
JUDGE=1 bash runs/round2/run.sh D-handoff  $B DIRECTON_JEV_HANDOFF=1
JUDGE=1 bash runs/round2/run.sh D-turn     $B DIRECTON_JEV_TURN=1
JUDGE=1 bash runs/round2/run.sh D-both     $B DIRECTON_JEV_HANDOFF=1 DIRECTON_JEV_TURN=1
uv run python runs/round2/analyze.py D-base D-handoff D-turn D-both
```

- 우리 172문항은 우리 Mock 데이터 기준이라 공식 데이터로 바꾼 Mock에서는 함수 결과가 not_found가 된다. **이 A/B는 우리 Mock(`DIRECTON_MOCK_*` 지정 없이)으로 돌린다.** 말 끝·인계 판단은 함수 데이터와 거의 무관하다
- 공식 예시 문항·음성이 있으면 `CASES=… AUDIO=…`로 같은 4개 arm을 한 번 더 돌린다. 인계 기준은 매뉴얼에 따라 달라질 수 있다

판정(점수는 같은 설정 반복 시 ±2.5점 흔들리므로 아래 구조 지표로 본다):

| 스위치 | 켜는 조건 | 보는 지표(analyze 열) |
|---|---|---|
| `DIRECTON_JEV_TURN` | 말 끝 전 발화가 D-base보다 **2건 이상 줄고**, 첫 소리 1.5초 안 문항 수가 줄지 않음 | `spoke_before_end`, `first_sound_p95`, `first_sound_le_1_5` |
| `DIRECTON_JEV_HANDOFF` | 인계 재현율이 오르고 오탐이 늘지 않음, 인계 턴 답 지연이 1.5초 구간을 넘지 않음, 단가가 예산 안 | `handoff_recall`, `handoff_false_pos`, `after_tool_answer_p95`, `jev_h` |

말이 끝나기 전에 답을 준비하는 상담원

같은 시스템을 다섯 단계로 설명합니다. 모든 단계가 전체 구성 요소를 다루고, 아래 단계로 갈수록 동작 방식과 근거가 자세해집니다.

1단계 · 한 문장

고객 음성을 실시간으로 들으며 말이 끝나기 전에 답을 미리 준비하고, 말이 끝났다고 판단하는 순간 준비된 첫마디를 바로 내보낸 뒤, 필요한 업무를 함수로 처리해 음성으로 답하는 상담원 서버입니다.

~10ms말 끝 확정 → 첫 소리 송신
85.6속도 점수 (172문항, 단순 조합 25.2)
70.7시스템 점수 추정 (단순 조합 53.1)

2단계 · 다섯 부품

왼쪽에서 오른쪽으로 음성이 흐릅니다. 3번이 이 시스템의 핵심입니다.

LISTEN① 듣기측정기 음성을 실시간 받아쓰기(STT)하고 목소리 구간을 감지(VAD)
DECIDE② 말 끝 판단침묵 길이, 인식된 문장 끝 모양, 발화 길이로 고객 말이 끝났는지 결정
PREPARE③ 미리 준비고객이 잠깐 멈춘 순간 LLM 답 생성과 첫 문장 음성 합성을 시작
SPEAK④ 답하기확정 즉시 캐시 첫마디 송신 → LLM 답을 문장 단위 음성으로
ACT⑤ 업무 처리주문 조회·취소 등은 Mock API 함수로. 번호·상품명은 정확히 맞춰서

3단계 · 부품별 역할과 사용 기술

부품하는 일기술
서버·세션측정기 프로토콜(session.start → PCM → 응답 PCM + agent.transcript + turn.end), 동시 세션, 한 연결 다중 턴Python asyncio, websockets
STT20ms 프레임을 묶어 실시간 전사, 말 끝에서 최종 텍스트 확정gemini-3.5-transcribe-live
VAD프레임마다 목소리 확률Silero VAD (ONNX, 로컬)
턴 결정기"지금 말이 끝났나"를 매 프레임 판단보정한 규칙 표 (텍스트 종류 × 발화 길이 → 대기 시간)
선호출·선합성멈춘 순간 LLM 시작, 첫 문장 음성 미리 합성, 최종 텍스트가 같으면 재사용자체 구현
첫마디확정 즉시 내보내는 짧은 문구 (상황별 3종)캐시 PCM
LLM 응답기매뉴얼 기반 응답, 함수 호출 루프, 문장 단위 TTS 연결gemini-3.5-flash-lite (대체 3.1-flash-lite)
정규화한국어 숫자·철자·날짜 → 함수 인자, 상품명·옵션 카탈로그 맞춤, 번호 교정자체 규칙
TTS문장 → 16kHz 음성edge-tts (대체 Gemini TTS)
Mock API함수 14개, 정해진 입력 → 정해진 출력, 호출 기록표준 라이브러리 HTTP 서버
평가 도구테스트 음성 합성·통화 환경 증강, 측정기, 채점기, 오프라인 평가기eval/*

4단계 · 한 턴의 시간 흐름

고객의 말 끝을 기준으로, 무엇이 언제 시작되는지 보여 줍니다. 오디오는 확정 전에 절대 나가지 않습니다.

고객·본 응답 음성 미리 준비 (송신 안 함) 첫 소리
시점일어나는 일
세션 시작session.start에서 고객 정보·이전 대화·현재 시각·tools_url을 받고, 함수 목록 조회와 STT 연결을 백그라운드로 시작. 시스템 프롬프트(매뉴얼 + 규칙 + 세션 정보)를 만듦
말하는 중20ms마다 STT 전송, VAD 판정. 60ms 미만 소리 조각은 잡음으로 버림
침묵 200ms① STT 최종 텍스트 확정 요청 ② 현재 텍스트로 LLM 선호출 ③ 첫 문장 음성 선합성. 오디오는 보내지 않음
확정 텍스트 도착선호출 텍스트와 다르면 그 텍스트로 다시 선호출
말 끝 판정텍스트 종류(완결·연결어미·간투사·숫자 미완)와 발화 길이로 정한 대기 시간을 채우면 확정 (대략 0.7~2초)
확정 +~10ms확정 시점 텍스트로 첫마디를 골라 송신 (불만 → 사과 / 조회 → "확인해 드릴게요" / 기본 "네, 고객님."). 측정되는 첫 소리
본 응답최종 텍스트가 선호출 텍스트와 같으면(정규화 비교) 선호출 결과·선합성 음성을 이어 씀, 다르면 새로 호출
함수 호출인자 정규화·교정·검사 후 X-Session-Id를 붙여 호출 → 결과를 넣어 LLM 재호출 (최대 3라운드). 늦으면 필러
마무리agent.transcript → turn.end. 연결이 유지되면 대화를 쌓아 두고 다음 발화를 받음
안전 장치확정 후 20초 상한 · LLM 첫 이벤트 2.5초 없으면 대체 모델 · 응답 300자 상한 · 실패 시 캐시 사과 + turn.end

5단계 · 세부 설계와 근거

근거: 첫 소리는 확정 후 약 10ms에 나갑니다. 그래서 말 끝 판정에 1초 넘게 써도 속도 만점(1.5초) 안에 들어오고, 그 시간을 잘못 끊기를 줄이는 데 씁니다.

①서버·세션

  • 시작 시 예열: VAD·Smart Turn 첫 추론, 캐시 문구 합성, LLM 모델별 짧은 요청, STT 연결. 404 모델은 대체 목록에서 제외
  • 의존성은 생성자 주입. VAD·결정기는 세션마다 새로. 계약은 agent/core/types.py
  • debug:true일 때만 디버그 이벤트(체험 데모용). 없으면 측정기 경로와 바이트 단위로 동일
  • 턴마다 JSON 로그: 단계별 시각, 결정 이유, 선호출 재사용, 첫마디–본 응답 공백
agent/server.pyagent/session.py

②STT

  • 100ms 묶음 전송. 중간 결과는 덮어쓰고 확정 결과는 이어 붙임. 확정 요청 → 최종 텍스트 p50 0.4초
  • 부분 결과 숫자 복원: 확정 텍스트 자릿수가 틀리고 직전 중간 결과가 맞으면 교체 (지연 0)
  • 일괄 재인식은 1.5~3초라 기본 끔. 숫자 정확도 74% (전화 채널 63~68%), 설정으로는 개선 안 됨
  • Soniox 어댑터 구현됨, 키가 생기면 환경변수로 전환
providers/gemini_stt.pystt_recheck.py

③VAD·턴 결정기

  • Silero는 512샘플 단위만 받아 20ms 프레임을 다시 자름 (1ms 미만)
  • make_detector(): 텍스트 9종 × 발화 길이 4구간 → 대기 시간. 빈·중립 ≥900ms, 완결 ≥700ms, 연결어미·간투사·조사 최대 2초, 숫자 묶음 사이 쉼은 보류
  • 보정셋 771발화(쉼 위치를 아는 합성, 화자·문장 비중복 분할): 잘못 끊기 42.5% → 15.7%, 1.1초 이하 쉼에서는 1.3%
  • Smart Turn v3.2는 한국어 통화 음성에서 구분력 없음(AUC 0.57) → 판단에 미사용. 잡음 VAD 래퍼는 기본 끔(AD8)
agent/turn/vad.pydetector.pyrules.py

④미리 준비

  • 재사용 판단: 공백·문장부호 제거, 한글 숫자 → 아라비아 숫자로 바꾼 뒤 비교. 재사용률 2/20 → 24/30
  • 선합성 음성은 버퍼에만. 확정 전 송신 0을 테스트로 보장
  • 확정 텍스트가 바뀌면 그 텍스트로 즉시 다시 선호출
session.py · _PreSynth · match_key

⑤LLM 응답기

  • 프롬프트 고정부(역할, 음성 규칙, 함수 규칙, 상태별 안내, 매뉴얼) + 가변부(시각, 고객 정보, 이전 대화 요약·번호, "이미 '첫마디'라고 말했다")
  • 규칙: 호칭 반복 금지, 함수 먼저 호출 후 말하기, 인계 조건이면 transfer_to_agent(영업시간 외 request_callback), 결과 핵심 필드 포함 3~4문장
  • 안전망: 번호 교정(발화·고객 주문 목록 기준), 자릿수 검사, 연결 보장, 필러 150ms, 300자 상한
  • 대체 모델: 첫 이벤트 2.5초 없거나 오류 → 3.1-flash-lite (출력 시작 후엔 전환 없음)
  • 오프라인: 함수 완전 일치 0.71 → 0.89, judge 58.9 → 65.3
agent/prompts.pyresponder.pyfallback_llm.py

⑥정규화

  • 숫자: "공일공/영일영", 자릿값("천이백삼십사"), 아라비아 혼합, "이요" 어미 구분
  • 영문 철자 읽기(디 이 엠 오 → DEMO), 날짜·시간("다음 주 월요일", "오후 세 시")
  • 카탈로그: 정확 → 별칭(엑스라지 → XL, 회색 → 그레이) → 부분 → 유사도. 후보가 둘 이상이면 원문 유지
agent/normalize.pyagent/catalog.py

⑦TTS·출력

  • edge-tts MP3 → ffmpeg 스트리밍 디코드 → 16kHz. 첫 바이트 p50 0.47초
  • 음성 구간 RMS 3000으로 정규화, 앞 무음 제거 → 첫 100ms가 측정기 유성음 기준(RMS 300)을 넉넉히 넘음
  • 캐시 문구(첫마디·필러·사과)는 디스크 저장 후 시작 시 메모리 적재
providers/edge_tts.pyagent/tts_cache.py

⑧Mock API

  • /tools, /tools/{name}, /calls — Starter Kit과 같은 형식
  • 키 인자(전화번호·주문번호·상품명·옵션)는 문자 그대로 일치해야 matched. 자유 텍스트 인자는 판정 제외
  • 상태별 결과 (예: 배송 중 취소 → not_allowed). 공식 데이터가 오면 파일만 교체
mock_api/

⑨평가 체계

  • 테스트셋 172문항: 범주 7종, 화자 11종, 채널 3·잡음 5·SNR·음량·패킷 손실·말 속도
  • 측정기(Starter Kit 확장, 같은 속도표) · 채점기(함수 키 인자, Gemini judge) · 오프라인 평가기(LLM·STT·턴 시뮬레이터)
  • 시스템 점수 추정: 처음 63.0(응대 제외) → 1차 70.7 · 단순 조합 53.1
  • 체험 데모: 브라우저 마이크 통화, 인식·판단·함수·지연 표시, 이전 대화 주입

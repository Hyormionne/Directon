## 규칙 (`agent/catalog.py`)

1. 공백·대소문자 무시 정확 일치
2. 옵션 별칭(동의어 묶음, 양방향): 사이즈 XS/S(에스·스몰)/M(엠·미디엄)/L(엘·라지)/XL(엑스라지·엑스엘)/XXL(투엑스라지·2XL)/XXXL/FREE(프리사이즈), 색상 그레이(회색)·블랙(검정·검은색)·화이트(흰색·하얀색)·네이비(남색)·레드(빨강)·블루(파랑)·핑크(분홍)·베이지·카키·퍼플(보라)·실버(은색)·골드·그린·옐로·브라운·오렌지·아이보리·민트(+영문). 한글 수 읽기("이백칠십"→270, "십오 인치"→15인치). 끝말("사이즈", "색", "으로", "요" 등)은 떼어 보고 다시 맞춘다. 별칭에 있는 말인데 그 상품에 해당 옵션이 없으면(후드티 "XXL") None.
3. 부분 일치(유일할 때만): 표현 ⊂ 카탈로그 또는 반대. 숫자만인 옵션 표현은 "15"→"15인치"처럼 단위만 붙은 옵션에만("28"→"280" 금지). 상품명은 낱말 일치도(카탈로그 이름 낱말이 가장 많이 든 상품이 유일할 때).
4. 문자 유사도 0.75 이상이고 2등과 0.1 이상 차이.
- 애매하거나 모르면 None → 원문(strip) 유지. 예: "무선"(이어폰·충전기) → 그대로.

## 연결

- `normalize_args(tool, args, schema, now, catalog=None)`: catalog 객체를 주면 그것을, `False`면 끔, `None`이면 기본 카탈로그를 **상품 도구(get_product_info, check_stock)이거나 스키마에 product_name이 있을 때만** 쓴다(임의 도구의 기존 동작 보존). 응답기는 기존처럼 4인자로 부른다.
- 기본 카탈로그: `DIRECTON_CATALOG_PATH`(공식 데이터가 오면 이 경로로 교체), 없으면 `mock_api/data/mock_data.json`. 지연 로드·경로별 캐시. 파일이 없거나 형식이 다르면 정규화 생략. 형식: `{"products":[{"name","options":[{"name"}|str]}]}`, 최상위 리스트, `{"products":{"상품명":[옵션]}}`.
- option은 해석된 상품명 기준으로 맞춘다. 상품이 카탈로그에 없으면 옵션은 손대지 않는다.

## 발견 이슈

- 프롬프트의 "상품을 종류 이름으로만 말해 상품명이 분명하지 않으면 먼저 확인" 규칙 때문에 LLM이 "경량 패딩 조끼"·"캠핑 의자"처럼 분명한 이름도 되묻는다(T0075 매번). 이제 카탈로그 정규화가 있으니 "일단 들은 이름으로 호출" 쪽으로 완화할 여지가 있다(prompts.py는 이 Task 범위 밖).
- 측정 중 Gemini 404 오류(폴백 모델 포함)가 실행마다 1~2건 났다. 재실행하면 정상.

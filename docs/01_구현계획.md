## 1. 목표 재정의

초안의 목표("체감 지연 최소화 + 잘못 끊기 최소화")는 유지하되, 대회 배점(응대 50 / 함수 20 / 속도 30)에 맞춰 우선순위를 다시 잡는다.

1. **말 끊기 0에 가깝게**: 말 끝 전에 소리가 나가면 그 문항 속도가 0점이고, 부분 발화로 답하게 되어 응대·함수 점수도 함께 잃는다.
2. **첫 유성음 1.5초 이내**: 속도 점수는 0.5초 단위 구간제다. 1.5초 안이면 만점이므로 "100ms까지 줄이기"는 목표가 아니다.
3. **정확한 함수 호출**: 함수 이름과 인자가 미리 정의된 값과 일치해야 한다(`matched`). 인자 정규화가 핵심이다.
4. **매뉴얼을 지키는 응답**: 정식 매뉴얼이 공개되면 응답 템플릿과 프롬프트에 반영한다.

## 2. 초안 대비 변경 사항

| 초안 항목 | 결정 | 이유 |
| --- | --- | --- |
| 브라우저 마이크 + FastAPI | **삭제** → `websockets` 서버(9000번 포트)가 측정기 프로토콜을 구현 | 입력은 측정기가 보내는 PCM |
| 통신사 도메인, 케이스 20개 | **쇼핑몰로 교체**. 케이스는 정식 매뉴얼과 14개 함수에 맞춰 정의 | Starter Kit 도메인 |
| 다중 턴 확인 질문(예/아니오 판정) | **축소**. 세션당 응답이 1회라서, 확인은 "응답 문장 안의 확인 표현"으로 처리. `history`에 확인 질문이 있었으면 그 맥락으로 판정 | 측정기는 `turn.end` 후 세션 종료 |
| JEV 턴 종료(Noul) + 250ms 타임아웃 | **보조 신호로 강등**. 1차 신호는 로컬 VAD 침묵 + Smart Turn v3.2 | 한국에서 JEV 왕복이 200~650ms로 추정되어 예산 초과 |
| JEV 케이스 판정이 본안, 플랜 B가 보조 | **역전**: 플랜 B(로컬 임베딩)가 기본, JEV는 백그라운드 판정 + 로그 비교 | 지연·한국어 품질 미검증 |
| 엔드포인팅 대기 100 / 500 / 1200ms | **400 / 600 / 900ms**(상한 1100ms) | 1.5초 예산 안에서 잘못 끊기 최소화 |
| Gemini 2.5 Flash TTS | **`gemini-3.8-flash-tts`**(16kHz 출력 옵션 확인 필요). 대체: ElevenLabs Flash v2.5 | 2.5는 최신 문서에서 빠짐. 첫 음성 지연이 미검증 |
| GPT-5.4 mini | **유지**(`gpt-5.4-mini`, reasoning `none`, Responses API). 비교 후보: `gpt-6-luna` | 존재 확인 |
| 바지인 | **후순위** | 측정기는 상담원 발화 중에 말하지 않음 |
| 확인 문구 사전 합성 캐싱 | **핵심으로 승격**: "첫 마디 캐시"가 속도 점수를 책임진다 | 첫 유성음 도착 시각만 측정 |

## 3. 시스템 구성

```
측정기 ──WS(PCM 20ms)──▶ [Session]
                           ├─ AudioIn ─┬─▶ Soniox STT (stt-rt-v6, ko) ──▶ partial/final 텍스트
                           │           ├─▶ Silero VAD (512샘플 재분할) ──▶ 침묵 길이
                           │           └─▶ 링버퍼(최근 8초) ──▶ Smart Turn v3.2 (ONNX)
                           ├─ TurnDetector: 침묵 + Smart Turn + 종결어미 규칙 (+JEV Noul) ──▶ "말 끝" 확정
                           ├─ Router: 플랜 B 임베딩(KURE-v1) 기본 / JEV Choice 백그라운드 ──▶ 케이스 + 구간
                           ├─ Responder
                           │    ├─ 첫 마디: 캐시 PCM 즉시 송신 (케이스별 또는 공통)
                           │    ├─ 안내형 확실 구간: 템플릿 전체 캐시 → LLM 생략
                           │    └─ 나머지: gpt-5.4-mini 스트리밍 + 툴 호출 ──▶ 문장 분할
                           ├─ ToolClient: GET /tools, POST /tools/{name} + X-Session-Id, 인자 정규화
                           ├─ TTS: Gemini Flash TTS 문장 단위 → 16kHz PCM (대체: ElevenLabs)
                           └─ Out: PCM 송신 + agent.transcript + turn.end, 턴 로그(JSON)
Mock API 서버(8100) ◀── ToolClient
```

### 3.1 세션 타임라인 (목표값)

| 시점(말 끝 기준) | 일어나는 일 |
| --- | --- |
| 말하는 중 | partial마다(약 300ms 디바운스) 플랜 B 판정, 확실 구간이면 첫 마디·템플릿 준비. JEV는 백그라운드에서 판정하고 결과를 텍스트와 함께 캐시 |
| +200ms 침묵 | Soniox `finalize` 전송, Smart Turn 추론, 현재 텍스트로 LLM **선호출 시작**(재생은 보류) |
| +400ms | Smart Turn p ≥ 0.7이고 종결어미가 끝남 → **말 끝 확정** |
| +600ms | 애매 구간 → 말 끝 확정 |
| +900ms | 미완료 판정이어도 확정(연결어미·간투사로 끝났으면 1100ms까지) |
| 확정 +≤50ms | 첫 마디 캐시 PCM 송신 → **첫 유성음 ≈ 0.45~1.15초** |
| 이후 | 본 응답 문장 TTS를 순서대로 송신. 첫 마디 뒤 공백이 800ms를 넘을 것 같으면 필러("잠시만요, 확인해 볼게요") 삽입 |
| 끝 | `agent.transcript`(전체 응답 텍스트), `turn.end` |

- 확정 전에 사용자 음성이 다시 감지되면 선호출 LLM·준비한 응답을 모두 취소하고 처음으로 돌아간다(초안 6번 유지).
- final 텍스트가 선호출 때 쓴 텍스트와 다르면 LLM을 다시 호출한다. 같으면 선호출 결과를 그대로 쓴다.

## 4. 모듈별 설계

### 4.1 서버·세션 (`agent/server.py`, `agent/session.py`)
- `websockets.serve`, 세션마다 asyncio 태스크 그룹을 둔다. 동시 세션은 최소 8개를 목표로 한다(측정기 기본값 4의 두 배).
- 외부 연결(httpx AsyncClient, OpenAI·Gemini 클라이언트)은 프로세스 전역에서 재사용하고 시작할 때 미리 예열한다.
- `session.start`의 `history`, `caller`, `now`, `tools_url`을 세션 상태로 보관한다.

### 4.2 STT (`agent/stt_soniox.py`)
- `wss://stt-rt.soniox.com/transcribe-websocket`, 인증은 `Authorization: Bearer` 헤더(시작 메시지의 `api_key`는 2027-01-15부터 거부).
- 설정: `model: stt-rt-v6`, `audio_format: pcm_s16le`, `sample_rate: 16000`, `num_channels: 1`, `language_hints: ["ko"]`, `context`(쇼핑몰 용어, 함수 인자 예시, history 요약).
- 엔드포인트 감지는 켜 두되 `<end>`는 **말 끝을 앞당기는 보조 신호**로만 쓴다(상한이 예산을 다 씀).
- 침묵 200ms에 `{"type":"finalize"}`를 보내고 `<fin>`을 기다린다. 20초 이내 간격으로 keepalive를 보낸다.
- 세션 연결은 `session.start`를 받는 즉시 연다(오디오보다 먼저).
- 한도: 기본 동시 스트림 10개, 분당 100요청 → 동시성 4~8에서는 충분. 가격 $0.12/시간.

### 4.3 VAD·턴 감지 (`agent/vad.py`, `agent/turn.py`)
- Silero VAD 6.x: 20ms 프레임(320샘플)을 모아 512샘플로 다시 잘라 넣는다(청크당 1ms 미만).
- Smart Turn v3.2(BSD-2, ONNX 8MB, 한국어 정확도 97% 내외로 보고됨, CPU 13~95ms): 최근 8초 오디오로 완료 확률을 얻는다.
- 텍스트 규칙(`agent/korean_rules.py`):
  - 끝남 쪽: `-요, -다, -까, -죠, -니다, -는데요, -거든요, -세요`, 단답("네", "아니요", 번호만)
  - 보류 쪽: `-고, -서, -면, -는데, -니까`, 간투사("어", "음", "그"), 숫자를 불러주는 중(자릿수 미달)
- 결정 함수 하나에 위 신호를 모으고, JEV Noul 결과가 시간 안에 오면 가산한다. 인터페이스는 `TurnSignal → wait_ms`로 고정해 모델을 바꿀 수 있게 한다.
- 상태 보정: `history` 마지막 상담원 발화가 질문이면 단답 예상으로 보고 대기를 줄인다. 번호·주소 수집 턴이면 상한을 늘린다.

### 4.4 케이스 라우터 (`agent/router/`)
- **플랜 B(기본)**: KURE-v1(568M, 1024차원, MIT)으로 케이스별 예시 발화 20~50개를 시작할 때 임베딩해 메모리에 올려 둔다. 케이스 점수는 상위 3개 예시 유사도의 평균. numpy 약 50줄로 구현하고 semantic-router는 쓰지 않는다. CPU 지연은 실측하고, 느리면 GPU나 경량 모델로 바꾼다.
- **JEV(백그라운드)**: `POST https://api.typesafe.ai/v1/systemone`, 모델은 `jev-1.14.0`으로 고정. 케이스 Choice와 턴 종료 Noul을 **한 요청에 함께** 보낸다. "해당 없음"은 별도 Noul로 보강한다(첫 선택지 편향 대응).
- 3구간 시작값(실측 후 재조정):

| 구간 | 플랜 B | JEV | 동작 |
| --- | --- | --- | --- |
| 확실 | s1 ≥ 0.80, s1−s2 ≥ 0.05, s1 > s_none | p1 ≥ 0.85, p1/p2 ≥ 2 | 케이스 첫 마디 + 템플릿(안내형) 또는 LLM(실행형) |
| 애매 | 0.65 ≤ s1 < 0.80 | 0.5 ≤ p1 < 0.85 | 공통 첫 마디 + LLM(상위 2개 후보를 프롬프트 힌트로 제공) |
| 없음 | s1 < 0.65 또는 s_none 최고 | p1 < 0.5 | 공통 첫 마디 + LLM |

- 고위험(취소·환불·결제·해지) 케이스는 확실 기준을 높이고, 템플릿만으로 끝내지 않고 항상 LLM과 함수를 거친다.
- 라우터 결과는 **첫 마디 선택과 LLM 힌트**에만 쓴다. 함수 호출 여부는 LLM이 최종 결정한다(함수 점수 보호).

### 4.5 응답 생성 (`agent/responder.py`, `agent/llm.py`)
- `gpt-5.4-mini`, Responses API 스트리밍, `reasoning.effort: none`, verbosity low, strict 툴 스키마.
- 시스템 프롬프트 앞부분(매뉴얼 요약, 툴 정의, 말투 규칙)을 고정해 프롬프트 캐시가 적중하게 한다. 세션별 내용(now, caller, history, 라우터 힌트, 첫 마디 문구)은 뒤에 붙인다.
- **첫 마디와 본 응답이 이어지게** 프롬프트에 "이미 '{첫 마디}'라고 말했다. 그 뒤부터 이어서 말하라"를 넣는다.
- 출력 규칙: 2~3문장, 숫자는 읽기 쉬운 형태, 이모지·마크다운 금지.
- 툴 루프: 툴 호출이 나오면 필러를 재생하면서 호출하고, 결과를 받으면 바로 다음 응답을 스트리밍한다.
- 비교 실험: `gpt-6-luna`(reasoning을 `none`으로 명시). 툴 호출 정확도와 첫 토큰 지연이 둘 다 같거나 나으면 교체.

### 4.6 함수 호출 (`agent/tools.py`, `agent/normalize.py`)
- 세션 시작 때 `GET {tools_url}/tools`로 툴 정의를 받아 LLM 툴로 변환한다(프로세스 캐시).
- 모든 호출에 `X-Session-Id: {session_id}`를 붙인다.
- 인자 정규화를 3중으로 둔다.
  1. 프롬프트: 주문번호·전화번호 형식 예시
  2. 코드: 한국어 숫자 읽기("공일공", "일영영일") → 숫자, 영문 철자 읽기("디이엠오") → 대문자, 전화번호 하이픈 제거, 날짜를 `now` 기준 절대일로 변환
  3. 스키마 검증: 형식이 맞지 않으면 LLM에 재질의 한 번, 그래도 안 되면 고객에게 다시 묻는 응답
- `caller.phone`이 있으면 고객에게 다시 묻지 않고 그대로 쓴다.

### 4.7 TTS·오디오 출력 (`agent/tts/`, `agent/audio.py`)
- 기본: `gemini-3.8-flash-tts`(대안 `gemini-3.8-flash-lite-tts`), 한국어 음성 하나로 고정(예: Kore), 스타일 프롬프트는 "친절한 상담원, 또박또박".
- 출력: `response_format.sample_rate=16000`이 되면 그대로 쓰고, 안 되면 24k→16k 변환(스트림은 `soxr.ResampleStream`, 캐시는 `resample_poly(2,3)`).
- TTS 입력은 스트리밍이 안 되므로 **LLM 출력을 문장 단위로 끊어 문장마다 따로 호출**하고, 다음 문장 합성을 미리 시작한다(파이프라인).
- **캐시(빌드 시 1회 합성, 디스크 저장)**: 공통 첫 마디 여러 종, 케이스별 첫 마디, 안내형 템플릿 전체 응답, 필러, 오류 안내 문구. 서버 시작 때 메모리로 올린다.
- 대체 경로: 문장 TTS가 정해진 시간(예: 1.2초)을 넘기면 ElevenLabs Flash v2.5(`pcm_16000`, 약 200ms로 알려짐)로 다시 요청한다. 0단계 실측에서 Gemini가 느리면 기본을 ElevenLabs로 바꾼다.
- 송신: 첫 덩어리는 즉시, 이후는 몰아서 보내도 된다(측정은 도착 시각 기준). 앞뒤 무음을 잘라 첫 프레임부터 RMS가 300 이상이 되게 한다.

### 4.8 Mock API 서버 (`mock_api/server.py`)
- Starter Kit 템플릿을 확장한다. `lookup()`은 `(함수명, 정규화 전 인자)`가 미리 정의된 입력과 정확히 같을 때만 `matched=True`.
- 데이터 파일은 `mock_api/data/*.json`으로 분리해 정식 14개 함수 명세가 공개되면 데이터만 바꾸면 되게 한다.
- `GET /tools`, `POST /tools/{name}`, `GET /calls` 경로와 응답 형식은 템플릿 그대로 유지한다.

### 4.9 로그·지표 (`agent/logging.py`)
- 턴마다 JSON 한 줄: 세션 ID, 프레임 기준 타임스탬프(첫 음성, 침묵 시작, finalize, `<fin>`, Smart Turn 결과, 말 끝 확정, 첫 마디 송신, LLM 첫 토큰, 툴 호출·응답, 문장별 TTS 요청·첫 바이트, `turn.end`), 확률값, 라우터 결과(플랜 B, JEV 둘 다), 최종 텍스트.
- 지표

| 지표 | 정의 | 목표 |
| --- | --- | --- |
| first_sound p50 / p95 | 측정기 기준 | p95 ≤ 1.3초 |
| 잘못 끊은 비율 | `spoke_before_end` 비율 + 확정 후 음성 재개 비율 | ≤ 1% |
| 함수 일치율 | 기대 함수·인자와 `matched` 일치 | ≥ 95% |
| 응대 품질 | LLM 심사 점수(매뉴얼 체크리스트) | 측정 후 기준 설정 |
| 확실 구간 정밀도 | 플랜 B / JEV 각각 | ≥ 95% |
| 미리 준비 적중률 | partial 판정 = final 판정 비율 | 측정만 |
| 구간별 지연 | STT finalize, LLM TTFT, TTS 첫 바이트, JEV | 병목 확인용 |

## 5. 평가 환경 (`eval/`)

Starter Kit 데모 음성은 영어라서 한국어 테스트셋을 직접 만든다.

1. **시나리오**: 쇼핑몰 CS 발화 150개 이상. 각 항목에 기대 케이스, 기대 함수·인자, 응답 체크리스트를 둔다. 비율은 안내형 / 실행형 / 범위 밖 / 다중 턴(history 있음)으로 나눈다. GPT로 초안을 만들고 사람이 검수한다.
2. **음성 합성**: 우리 TTS와 다른 목소리 여러 개로 합성한다(Gemini 다른 음성, ElevenLabs 등). 16kHz mono로 변환하고 `meta.json`의 `speech_end`를 계산한다.
3. **잘못 끊기 유도 세트**: 발화 중간에 300~900ms 쉼을 넣은 변형("주문번호가요… 디이엠오 일영영일이고요… 배송 언제 와요?"), 연결어미에서 쉬는 변형, 숫자를 천천히 부르는 변형.
4. **측정기**: Starter Kit `run_eval.py`를 그대로 쓰고(규격 호환 확인용), 함수 일치와 LLM 응대 심사를 더한 `score_full.py`를 추가한다.
5. **회귀 실행**: 설정을 바꿀 때마다 같은 세트를 돌려 `runs/<날짜>_<설정>/`에 결과를 남기고 지표를 비교한다.

## 7. 구현 단계

대회 일정이 확정되지 않았으므로 기간 대신 우선순위로 나눈다. 각 단계가 끝나면 그 상태로도 제출할 수 있어야 한다.

### 0단계: 실측 (1일) — 이후 설계를 결정
API 키를 준비하고, **우리 서버를 실제로 돌릴 위치에서** 아래를 각 30회 이상 잰다. 결과는 `docs/decisions/0단계_실측.md`에 남긴다.

| 측정 항목 | 통과 기준 | 실패 시 |
| --- | --- | --- |
| Soniox 한국어 정확도·finalize→`<fin>` 지연 | 지연 p95 ≤ 300ms | 말 끝 확정 시 `<fin>`을 기다리지 않고 마지막 partial 사용 |
| Gemini Flash TTS 문장당 첫 바이트, 16kHz 옵션 | p95 ≤ 1.0초 | ElevenLabs Flash를 기본으로 |
| gpt-5.4-mini 첫 토큰(툴 포함 프롬프트) | p95 ≤ 700ms | gpt-6-luna 비교, 프롬프트 축소 |
| JEV 왕복(Choice + Noul 묶음) | p95 ≤ 300ms면 동기 사용 | 백그라운드 로그 전용 |
| KURE-v1 CPU 임베딩(짧은 문장) | ≤ 40ms | GPU 또는 경량 모델 |
| Smart Turn v3.2 CPU 추론 | ≤ 100ms | 규칙 + 침묵만 사용 |

### 1단계: 끝까지 동작하는 최소 버전 (2~3일)
- 측정기 프로토콜, Soniox 연동, VAD 침묵 700ms 고정 엔드포인팅, gpt-5.4-mini 응답(툴 없음), 문장 단위 TTS, `agent.transcript`, `turn.end`
- 공통 첫 마디 캐시 송신
- Mock API 데모 함수 2개 구현, Starter Kit `run_eval.py` 통과
- 완료 기준: 한국어 음성 10개로 응답 생성, 에러 0, first_sound p95 ≤ 1.5초

### 2단계: 함수 호출과 평가 기반 (3~4일)
- 툴 루프, 인자 정규화, `caller` 활용, 필러
- 한국어 테스트셋 150개 이상 + 잘못 끊기 유도 세트, `score_full.py`, 턴 로그
- 완료 기준: 함수 일치율 ≥ 90%, 전체 지표를 자동으로 산출

### 3단계: 턴 감지와 케이스 라우팅 (3~4일)
- Silero + Smart Turn + 한국어 규칙으로 동적 대기(400 / 600 / 900ms), 상태 보정
- 플랜 B 라우터, 케이스별 첫 마디·안내형 템플릿 캐시, partial 기반 미리 준비, LLM 선호출과 취소
- JEV 백그라운드 판정 + 비교 로그
- 완료 기준: 잘못 끊은 비율 ≤ 1%, first_sound p95 ≤ 1.3초

### 4단계: 튜닝과 견고성 (남은 기간)
- 로그로 임계값을 재조정(플랜 B·JEV 구간, 턴 대기), 확인 거절·폴백 발화를 예시 집합에 추가
- 동시성 8 부하 시험, 외부 API 오류·타임아웃 대체 경로(TTS 대체, LLM 재시도, 끝까지 실패하면 캐시된 사과 + 인계 안내 + `turn.end`)
- 정식 매뉴얼·14개 함수·데이터가 공개되면 케이스·템플릿·Mock 데이터 교체
- 비용 점검: 395문항 기준 TTS 약 $5, STT·LLM 별도 계산

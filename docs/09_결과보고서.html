캐시한 첫 마디 + 상황별 첫 마디 정책

켬DIRECTON_OPENER_ADAPTIVE=1

확정 순간에 미리 녹음해 둔 짧은 첫 마디("네, 확인해 드릴게요.")를 보냅니다. 정책을 켜면 상황(조회, 단순 질문, 사과)에 맞게 고르고, 직전 턴과 같은 첫 마디나 채움말은 쓰지 않습니다.

얻은 것

  • 첫 소리 p50 0.83초. 속도 점수의 바탕입니다
  • 정책을 켜면 공식 감점 사례인 "모든 답변에 같은 채움말 반복"을 피합니다
  • 시스템 점수는 흔들림 폭 안에서 같았습니다(응대 −3.3, A/A 차이 4.0 안)

내준 것

  • 공식 기준은 "모든 응답을 채움말로 시작"을 좋게 보지 않는데, 첫 마디 사용률은 여전히 100%입니다
  • 이 테스트셋에서는 확정 순간에 답이 준비된 턴이 0회라 "첫 마디 없이 바로 답"이 한 번도 나오지 않았습니다
  • 문항이 단일 턴이라 반복 금지 효과를 측정하지 못했습니다. 데모 S17에서 사람이 확인해야 합니다

조회 결과 템플릿: 함수 결과의 사실로 첫 문장을 먼저 말하기

켬DIRECTON_TOOL_TEMPLATE=1

함수 문항의 속도 점수는 "말 끝 → 첫 소리" 점수와 "조회 결과 → 실제 답" 점수의 평균입니다. 템플릿을 켜면 LLM을 다시 부르는 동안 결과에 적힌 문장("주문이 취소되었습니다.", "배송중입니다.")을 먼저 말합니다. 숫자는 넣지 않고, 확실하지 않으면 말하지 않습니다.

얻은 것

  • 조회 뒤 실제 답 p50 2.33 → 0.99초
  • 측정기 기준 p95 2.29 → 1.02초. 모든 함수 문항이 100점 구간에 들어옵니다
  • 공식 속도(채움말 제외) 85.7 → 89.4
  • LLM 비용 변화 없음

내준 것

  • 문장이 기계적입니다("확인해 보니 현재 환불완료 상태입니다")
  • LLM이 이미 말한 문장을 피하려다 세부를 빼먹습니다(연습판 H0004: 바뀐 주소 생략 → 응대 0점)
  • 표현을 바꿔 같은 말을 반복합니다(H0024 "입금이 확인되었습니다. 입금이 확인되어…")
  • 공식 함수 결과에 고객용 문장이 없으면 거의 나가지 않습니다. 이 경우 해는 없고 효과도 없습니다

Jev로 사람 인계 판단(6개 기준, 하나라도 넘으면 인계)

켬DIRECTON_JEV_HANDOFF=1

건강 이상, 상담원 연결 요청, 강한 불만, 반복 실패, 법적 분쟁, 매뉴얼 밖 예외. 이 6개 기준을 한 번의 요청으로 함께 묻고, 기준마다 정한 임계값은 코드가 적용합니다. 영업시간 밖이면 콜백 접수로 돌립니다.

얻은 것

  • 인계 재현율 13 → 15/16, 불필요한 인계 0. LLM이 놓친 화난 배송 불만(T0038)과 이중 결제(T0041)를 잡았습니다
  • LLM 선호출과 같이 돌아 대부분의 턴에서 지연이 더해지지 않습니다(Jev p50 180ms)
  • 인계 기준이 코드와 임계값으로 드러나 기획서와 발표에서 설명하기 쉽습니다

내준 것

  • 인계 턴은 선호출을 버리고 다시 불러 실제 답이 늦어집니다(2.3~2.7 → 2.95초). 템플릿과 같이 켜면 1.8초로 상쇄됩니다
  • 질문당 Jev 약 5.5회 호출. 부분 텍스트가 바뀔 때마다 다시 묻습니다. 단가는 확인하지 못했습니다
  • 외부 의존이 하나 늘어납니다. 시간 초과면 LLM 판단으로 돌아가지만, 장애 구간에서는 시간 초과가 54회 났습니다
  • 연습판에서 약 복용 질문을 인계로 판단한 오탐 1건(H0031)이 있습니다
